# 나중에 확인할 것

사용자에게 물어야 하지만 작업을 멈추지 않으려고 미뤄 둔 질문. 사용자가 정한 방식이다(2026-09-28, A1–R01을 한 세션에서
항목마다 서브에이전트에 차례로 맡기며 진행할 때). 질문마다 **잠정으로 정한 값**으로 일단 진행했으므로, 답을 받으면
그 값을 쓴 곳을 고친다.

- 상태: `[ ]` 답 기다림 · `[x]` 답 받아 반영함(답 · 반영 커밋을 적는다) · `[-]` 없던 일로 함(사유)
- 번호는 항목별로 `Q-A1-1`, `Q-A1-2`, … 처럼 붙인다. 한 번 붙인 번호는 바꾸지 않는다.
- 칸: 질문 · 잠정(지금 쓴 값) · 근거(씬 ID · 줄 번호, 파일) · 영향(답이 다르면 고칠 곳).
- 1회독 후보(사실 · 의문 등)의 확정 · 기각은 여기 적지 않는다 — 후보 파일과 리뷰 도구(A3)가 맡는다.
  여기는 기준 · 분류 · 범위처럼 작업 방식이 걸린 질문만 둔다.
- 👤 리뷰 항목(RV1 …)에서 그때까지 쌓인 `[ ]` 질문을 같이 본다.
- **2026-09-29 사용자: 질문은 스토리 관련만 한다. 작업 방식은 Claude가 정한다.** 그래서 작업 방식 질문은 Claude가 정해
  `[x]`로 닫고 `결정` 줄을 달았다. 사용자에게 남은 것은 스토리 질문(`[ ]`)뿐이다. 앞으로도 여기에는 스토리 질문만 올린다.
- **2026-09-29 사용자(RV1): 원문을 읽어 가며 알 수 있는 질문(이름표가 누구인지 등)은 묻지 않는다.** Claude가 읽으면서 정하고 근거를 기록에 남긴다. 여기에는 원문으로 풀 수 없는 것만 올린다.

## A1 분석 범위 반영 + 인물 사전 (2026-09-28)

이름표 분류는 `annotations/dictionary/speakers.json`, 인물은 `annotations/dictionary/people.json`. 확인: `node tools/query.mjs who <이름>` ·
`node tools/query.mjs speaker <이름표>` · `node tools/query.mjs speakers <갈래>`. 답이 바뀌면 JSON을 고치면 다음 조회에서 DB가 다시 만들어진다.

### [x] Q-A1-3 호칭과 인물의 경계 — 묘사 · 직함 이름표

- **결정**(Claude, 2026-09-29 · 작업 방식): 잠정 기준 그대로 — 고유 이름은 인물, 묘사 · 보통 명사는 호칭. 묘사형 주요 인물은 1회독이 정체를 밝히면 정체 연결 후보로 잇는다.

  이 기준으로 괜찮은지, 되풀이해 나오는 묘사형 이름표는 인물 대상으로 세울지(정체가 이름 있는 인물로 밝혀지면 그때 후보로 잇는다).
- **잠정**: 위 기준 그대로. 묘사형 주요 인물은 1회독이 정체를 밝히면 정체 연결 후보로 잇는다.
- **근거**: `node tools/query.mjs speakers 호칭` · `speakers 인물`, speakers.json `notes`(Q-A1-3 표시).
- **영향**: speakers.json `호칭` ↔ `인물` 옮기기, 대상 수 · 인물 통계. 새 이름표를 분류하는 기준(1회독 · N3).

## A2 비인물 사전 (2026-09-28)

사전은 `annotations/dictionary/{places,orgs,concepts,incidents,items}.json`(+ `people.json`의 `person:퀸`). 확인: `node tools/query.mjs terms [종류] --names` ·
`node tools/query.mjs who <이름>`. 답이 바뀌면 JSON을 고치면 다음 조회에서 DB가 다시 만들어진다. 아직 이 대상들을 가리키는 기록(후보 · 언급)이 없어서
ID 접두(종류)를 지금 바꾸는 데는 비용이 없다.

### [x] Q-A2-1 이름 있는 탈것은 장소인가 물건인가

- **결정**(Claude, 2026-09-29 · 작업 방식): 잠정값 그대로 — 이름 있는 탈것은 `place:`(갈래 `탈것`).
- **질문**: 이름 있는 배 · 비행선 — `어드마이어 호`(범위 안 200줄, SEA, YOU, AGAIN · ch37) · `유토피아 호`(60, BOOM! THE GHOST!) · `승리의 날개 호`(51, OVER THE HORIZON · ARK GUARDIAN) —
  를 장소(`place:`)로 둘지 물건(`item:`)으로 둘지.
- **잠정**: 장소(`place:`, 갈래 `탈것`). 이야기의 무대가 되고 "어드마이어 호에서"처럼 위치로 많이 나온다.
- **근거**: d_main_37_02_e#3 · d_main_46_af_02#127 · fl:ark_guardian_22#117, places.json.
- **영향**: places.json → items.json으로 옮기고 ID 접두를 바꾼다(`place:어드마이어_호` → `item:어드마이어_호`). 앞으로 나올 탈것(열차 등)도 같은 쪽.

### [x] Q-A2-2 이름 있는 랩쳐 — 한 개체(인물)인가 종류(개념)인가

- **결정**(Claude, 2026-09-29 · 작업 방식): 잠정값 그대로 — 한 개체는 `person:`(갈래 랩쳐), 여럿을 가리키는 종류 · 등급은 `concept:`. 마더 웨일 · 크라켄 등은 1회독이 원문 근거로 정해 더한다.
- **질문**: A1 규칙은 "이름 있는 개체는 `person:`(갈래 랩쳐)"인데, 이름표가 없는 랩쳐 이름 중에는 여러 개체를 가리키는 종류 이름으로 보이는 것이 있다
  ("프레데터 3기, 침묵 확인." fl:absolute_18#1, "하베스터랑 구분이 안 가겠는데" d_main_47_01#50). 한 개체 = 인물, 종류 = 개념으로 나눠도 되는지.
- **잠정**:
  - `퀸`(870줄, "퀸의 직속. 이단…!" d_main_06_08_e#25) → 한 개체로 보고 `person:퀸`(people.json, 갈래 랩쳐). 본문 '퀸'은 퀸(마코토) · 언더월드 퀸과도 겹친다.
  - `프레데터`(54) · `블랙스미스`(27) · `하베스터`(17) → 종류로 보고 `concept:`(갈래 `랩쳐 종류`). `로드 급` · `타일런트 급`은 등급이라 `concept:`.
  - `마더 웨일`(90줄, ch21에 49줄 · 유실물 제목 "마더 웨일 아종 목격 보고") · `크라켄` 등은 개체인지 종류인지 몰라 v1에 넣지 않았다 — 1회독이 정해 더한다.
- **근거**: concepts.json(랩쳐 종류 3), people.json `person:퀸` note, `node tools/query.mjs search 마더 웨일`.
- **영향**: 종류가 바뀌면 people.json ↔ concepts.json으로 옮기고 ID 접두를 바꾼다. 1회독이 새 랩쳐를 어느 쪽에 넣을지의 기준.

## A3 1회독 준비 — 포맷 · 검증기 · 리뷰 도구 (2026-09-29)

형식 · 규칙은 [docs/annotations.md](annotations.md), 도구는 `node tools/records.mjs`(검증 `check` · 리뷰 `review` · 반영 `set` · 진행률 `progress` · 인계 `handoff`).
