# 카테고리 커버리지

조사일: 2026-09-17
기준: 직접 정리한 스토리 연관성 시트(368행) + blablalink 실측 수집 결과

## 한 장 요약

**구조적으로는 전 카테고리를 다룰 수 있다.** 스키마(T2-1)가 카테고리를 제한하지 않으므로
사이드·애장품·서브퀘스트도 노드로 올릴 수 있다.
다만 **원문 대사 자동 수집은 4종만 된다.** 나머지는 수동 주석으로 메워야 한다.

blablalink의 Shifty's Pad가 제공하는 스토리 섹션은 라우트 기준으로 정확히 4개다
(`/shiftyspad/scene-list/` 아래 `main`, `sudden`, `archive`, `attractive`).
여기 없는 것은 이 소스로는 나오지 않는다.

**2026-09-28 추가:** 블라링크에 없는 사이드 스토리 · 서브퀘스트 · 유실물 · 이벤트 유실물 · 이벤트(아카이브X 대부분)는
팬 사이트 **금서고**에서 보조로 받는다(사용자 결정) → [data-sources.md](data-sources.md) "8. 금서고". 아래 표의 금서고 칸.

## 시트의 `접근성` 칼럼이 커버리지를 그대로 예측한다

이벤트·퀘스트 92행을 아카이브 데이터와 대조한 결과:

| 접근성 | 데이터에 있음 | 없음 |
|---|---:|---:|
| 아카이브O (60행) | 56 | 4 |
| 아카이브X (32행) | 2 | 30 |

어긋났던 6건은 전부 제목↔ID 표기 차이였고, 모두 규명했다:

| 시트 제목 | 실제 ID | 왜 안 맞았나 |
|---|---|---|
| License to Kill | `event_ltk_*` | 약어 |
| A.C.P.U.! FREEZE! | `event_freezeacpu_*` | 어순 반전 |
| Bunny x 777 | `event_BunnyX777_*` | **ID에 대문자가 섞인 유일한 사례** |
| MEMORIES TELLER | `event_ce006_*` | 콜라보 번호가 ID다. 제목으로는 못 찾는다 |

별칭을 적용하면 **시트의 `아카이브O` 60행이 전부 데이터와 매칭된다.**
`아카이브X` 32행 중 30행은 매칭되지 않고, 2행(OVER THE HORIZON, STAR ANIS)은 데이터에 본문까지 있다
— 나중에 아카이브에 들어간 것으로 보인다. 데이터를 따른다(TODO.md "시트와 데이터가 다른 곳").

즉 **`아카이브O` = 자동 수집 가능, `아카이브X` = 대체로 불가**다.
아카이브X는 인게임 아카이브에 남지 않은 한정 이벤트이므로 blablalink에도 없다.

> 조사 때는 60/60이었지만 build.mjs의 제목 비교 키가 문장부호(`-',.!`)를 지우지 않아
> 실제 정규화에서는 11행이 빠져 있었다(2026-09-28 수정). 규칙은 docs/schema.md "시트 ↔ 데이터 연결".
별칭 표는 `annotations/aliases.json`.

> `event_BunnyX777`은 씬 ID를 정규식으로 다룰 때 `[a-z0-9]`로 짜면 통째로 빠진다.
> 실제로 이 조사 중에 한 번 놓쳤다. **ID 매칭은 항상 대소문자를 고려할 것.**

### 아카이브O인데 본문이 없는 이벤트 (43씬)

시트가 `아카이브O`로 표시했고 인게임에서는 읽히는데, CDN에 본문 파일이 없다:

| 이벤트 | ID | 누락 씬 |
|---|---|---:|
| BOOM! THE GHOST! | `event_boomtheghost1/2` | 28 |
| FOR REST | `event_forrest` | 15 |

인덱스에는 씬 목록이 정상적으로 들어 있으므로 blablalink 쪽 누락이다.
나중에 채워질 수 있으니 증분 수집(T6-1) 때 재시도 대상으로 둔다.

## 카테고리별 메모

### 메인 (✅)
49챕터. `d_main_CC_SS`(본편), `_s`/`_e`(컷신 A/B), `d_main_CCaf_SS`(방주 씬 143개)로 구성된다.
방주 씬은 별도 카테고리가 아니라 각 챕터에 속해 있다.

### 호감도 스토리 (✅) — 예상보다 수확이 크다
니케마다 호감도 레벨로 열리는 개인 스토리 5편. 데이터 이름은 `attractive`, 코드에서는 `episode`(`ep:`).

`roledata/{resource_id}-v2-ko.json`의 `attractive_scenario_list`에
편당 다음이 들어 있다:

```jsonc
{ "attractive_scenario_group_id": "d_nikke_emma_02",
  "scenario_title_locale": "죄의식",
  "attractive_level": 3,
  "condition_scenario_group_id": "d_nikke_emma_01" }   // ← 선행 편
```

**`condition_scenario_group_id`가 게임이 직접 들고 있는 선행 조건이다.**
965편 중 **756편에 선행 조건이 붙어 있다** — 호감도 스토리 범위의 선행 관계는
시트 없이 게임 데이터만으로 기계가 읽을 수 있다는 뜻이다.
`setup → payoff` 엣지(T3-4)의 시드로 바로 쓸 수 있다.

**캐릭터 193명 × 정확히 5편 = 965편. 시트의 193행과 양방향 완전 일치한다**
(`annotations/aliases.json` 적용 후 193/193, 미해결 0).

#### roledata를 그대로 믿으면 4명이 빠진다

`길티`(rid 400) · `신`(401) · `퀀시`(402) · `니힐리스타`(261)는
`attractive_scenario_list`가 **빈 배열**인데, 본문은 CDN에 정상적으로 있다:

```
/attractscene/d_nikke_guilty_01-ko.json      200
/attractscene/d_nikke_sin_01-ko.json         200
/attractscene/d_nikke_quency_01-ko.json      200
/attractscene/d_nikke_nihilister_01-ko.json  200
```

네 명 모두 5편씩. blablalink UI도 roledata를 그대로 읽으므로 이 호감도 스토리들을 보여주지 않는다.
`tools/blabla/known-gaps.json`에 slug을 적어두고 수집기가 직접 찾아내게 해뒀다.
새 캐릭터가 추가될 때 같은 일이 또 생길 수 있다. 캐릭터 목록(`nikke_list_v2`)에 있는데
roledata 목록이 비어 있는 캐릭터를 찾아 `attractscene` 파일이 있는지 확인하는 검증이 필요하다.

### 시트 ↔ 데이터 표기 차이

호감도 스토리의 캐릭터 이름이 시트와 어긋난 15건은 **전부 표기 차이이고 누락이 아니다.**
시트는 콜라보 캐릭터를 풀네임으로 쓰고, 게임 데이터는 단축명을 쓴다.

|---|---|
| 니시키기 치사토 | 치사토 |
| 이노우에 타키나 | 타키나 |
| 마키나미 마리 일러스트리어스 | 마리 |
| 시키나미 아스카 랑그레이 | 아스카 |
| 아야나미 레이 | 레이 |
| 카츠라기 미사토 | 미사토 |
| 아마기 유키코 | 유키코 |
| 에이다 웡 / 질 발렌타인 / 클레어 레드필드 | 에이다 / 질 / 클레어 |

rid 282는 니케 사쿠라(`d_nikke_sakura_*`), rid 836은 콜라보(`d_nikke_ce005_03_*`).
`resource_id`가 유일한 안전한 키다.

### 이벤트 · 퀘스트 (⚠️ 부분)
`archive_list.json` 62개 앨범 항목 안에 이벤트 씬이 중첩돼 있다.
각 항목은 `STORY` / `STORY I` / `STORY II` 자식을 1~2개 갖는다 (2부작 이벤트).
시트가 이벤트와 퀘스트로 나눈 구분은 **데이터에는 없다** — 둘 다 아카이브에 섞여 있다.
그 구분은 시트 작성자가 붙인 분류라 참고로만 연결해 둔다.

CDN에 파일이 없는 씬 43개가 있고 전부 콜라보 이벤트다
(`event_boomtheghost1_*` 등). 누락 목록은 `data/raw/manifest.json`에 있다.

### 애장품 (⚠️ 스토리 없음)
`equip/favorite_rare_map.json`의 SSR 21종이 **시트의 애장품 21건과 정확히 일치**한다.
`equip/{lang}/favorite_{id}.json`에서 이름·설명문·스탯·스킬은 받을 수 있지만,
**대사 데이터는 어디에도 없다.** `roledata`를 뒤져도 애장품에 걸린 시나리오는 없고,
`character_dialog_group_list`(42개)는 호감도 레벨로 해금되는 로비 대사다.

따라서 애장품은 **메타데이터 노드로만** 올리고, 내용은 수동 주석으로 채워야 한다.
소유 캐릭터는 게임 데이터(`name_code`)로 확정된다.

### 사이드 (✅ 금서고)
Second Affection / WORDLESS / MUDFISH / EDEN SPEAR / PRETTY STAR 5건(시트 표기는 EDEN SPHERE).
`event_*`, `d_side_*`, `d_sub_*` 패턴으로 추정 접근을 시도했으나 전부 404다.
Shifty's Pad에 사이드 스토리 섹션 자체가 없다.
→ 금서고에서 5건 전부 받았다(2026-09-28). 키 `side:…`. 공지 출시일로 메인 챕터 사이에 끼워 읽는다(SESSIONS.md).

### 돌발 (✅) — 시트에 없지만 데이터는 있다
`sudden_list.json` 27카테고리 / 301씬. **전초기지 건물별 대화**다:
커맨드 센터, 엘리베이터, 관측소, 경찰서, 호텔, 메이드 카페, 모던 바, 도서관,
병원, 극장, 법원, 교회, 쇼핑몰, 전파탑, 종합 체육관, 야외 수영장, 생화 공원 등.
ID는 `d_ex_{건물}_{번호}`.

시트에서 빠진 이유(다른 스토리와 접점이 적음)는 데이터로도 뒷받침된다 —
건물 단위로 닫혀 있고 메인 플롯 참조가 드물다. 다만 **인물 등장 데이터로는 값이 있다.**
중요도를 낮게 주고 인물 그래프에만 반영하는 쪽이 맞다.

### 서브퀘스트 (✅ 금서고)
번들에서 `subquest` / `sub_quest` / `side_story` 식별자를 찾지 못했다.
아카이브 씬이 `Locale_SubScenario` 로컬 테이블을 쓰는 것이 유일한 단서다.
→ 금서고에서 44건을 받았다(2026-09-28, T1-8). 메신저 형식 + 퀘스트 대화다. 키 `sub:…`.
몇 챕터 것인지는 게임 데이터에 없다. 디시 "서브 퀘스트 모음"에서 15개(31편)의 지역을 얻었다 → `annotations/subquest-regions.json`.
나머지 29개는 금서고 목록 순서로 보간한 대략의 자리, 유실물(`relic:…`, 55건)은 사용자가 게임 화면으로 준 지역(19~48지) + 18지 이하 잠정값 → `annotations/relic-regions.json`(TODO.md 결정 #9, 2026-09-29).

## 그래서 어떻게 할 것인가

1. **자동 수집분(메인·돌발·아카이브·호감도 스토리)** 이 뼈대다. 이미 손에 있다.
   분석(관계·중요도·선행)은 이 원문과 게임 데이터에서 **독립적으로** 한다.
2. ~~시트를 주석 레이어의 시드로 삼는다~~ → **시트는 참고자료다 (2026-09-28 결정).**
   시트에만 있는 것(사람이 나눈 유형 구분, ★중요도, 추천 선행)은 비교용으로 연결만 해 두고
   분석의 입력이나 정답으로 쓰지 않는다.
3. **원문 없는 것은 시트에만 있는 이름으로 남긴다**(`sheet:` 노드, 참고용). 금서고를 넣은 뒤(2026-09-28) 10건 —
   양쪽 다 없는 이벤트 · 콜라보와 시트 표기가 달라 못 이은 것이다.
   애장품 21건은 게임 데이터에 이름·설명이 있고 대사만 없다.
