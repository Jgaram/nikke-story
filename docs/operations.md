# 운영 — 세션 effort · 관리자 방식 (참고용)

**참고 자료다. 규칙이 아니다.** 사용자가 필요할 때 읽고 언제든 고친다. 기준: Opus 5.5(컨텍스트 1M), 2026-09-29.
작업 순서 자체는 [SESSIONS.md](../SESSIONS.md)가 정한다. 이 문서는 그 순서를 **어떻게 돌리는지**만 적는다.

돌리는 방법은 두 가지이고 섞어 써도 된다.

- **직접**: 사용자가 세션을 열고 "다음 일"이라고 한다. 끝나면 닫고 새 세션을 연다.
- **관리자**: 사용자가 관리자 세션 하나를 열면, 관리자가 작업 세션을 하나씩 열고 → 맡기고 → 확인하고 → 닫는다.
  사용자는 관리자를 가끔 교대만 한다(아래 "교대").

## effort — 하나로 통일: **high**

관리자가 여는 작업 세션에 effort를 따로 줄 방법이 없다(세션 생성 도구에 모델 칸은 있고 effort 칸은 없다).
그래서 관리자 · 작업 세션 모두 **high 하나로 맞춘다.** 계정 · 환경 기본값을 high로 두면 두 방식이 같아진다.

| 항목 | effort | 메모 |
|---|---|---|
| 1회독 R02–R99 | high | 줄거리 층 — 사실 · 의문 · 정체 연결을 Claude가 확정까지 한다 |
| 2회독 준비 B0a · B0b-1 · B0b-2 · 파일럿 P1 | xhigh, **직접** | 👤 — 뒤 100세션이 따르는 기준을 정하고, 끝에 사용자가 결과를 본다(아래 "사용자가 보는 곳") |
| 2회독 포맷 B1a · B1b | xhigh(직접) 또는 high(관리자) | 검증기 · 예시로 확인된다 |
| 2회독 M (1 · 2 · 3층) | high | 복선 · 암시 · 인물 변화 판단. 품질이 아쉬우면 이 구간만 올려 본다 |
| 코드 B2 · X2 · N2 | high | 테스트 · 검증기로 확인된다 |
| 분석 X1a–X1d · X3a–X3c | xhigh, **직접** | 작중 연대기 확정 · 중요도 등급 판정 — 원문 해석이 많고, 뒤(N3)가 따르는 기록 형식을 정한다(2026-10-08) |
| X3f-1 · X3f-1b · X3f-1c | xhigh, **직접** | 네 등급 도구 · 주역 명단 · 판단 원칙 — 다시 판정 432가 모두 따르는 기준. 끝이 👤(X3f-2)라 어차피 사용자가 연다(2026-10-09) |
| X3f 다시 판정 묶음(X3f-3 – X3f-7) · X3d · X3e | high(관리자) | 기준은 X3f-1 · X3f-2에서 굳었고, 판정은 검증기 · 시안 표 · 사용자 뒤집기로 확인된다. 아쉬우면 환경 기본값을 xhigh로 올려 관리자째 돌린다 |
| W0 · N3 | high | W0은 👤 사용자와 정하는 자리. N3은 2회독 M과 같은 성격 — 아쉬우면 올린다 |
| 관리자 | high | 원래는 medium이면 되는 일이지만 통일한다. 비용은 조금 더 든다 |

max는 권하지 않는다(비용 대비 차이가 작다). low는 관리자라도 실패를 놓칠 수 있어 권하지 않는다.

## 관리자 — 교대 시점

**작업 세션 20개 안팎마다 교대**하면 10~20%로, 사용자가 싫어하는 "컨텍스트가 많이 참"을 피한다. 연도 경계에서 끊는다.

## 관리자 절차

관리자는 **작업 세션의 대화를 읽지 않는다** — SESSIONS.md 상태 · git 커밋 · 진행률만 본다(관리자 컨텍스트를 아낀다).
**한 번에 하나씩 순서대로** 돌린다. 앞 세션의 인계 기록이 다음 세션의 입력이라 병렬로 돌리지 않는다.
예외: 공개 개요 W9a–W9r은 서로 인계가 없어 한 세션에서 에이전트로 병렬로 돌린다 — 방식은 SESSIONS.md W9 공통 "병렬 운용".

1. **다음 항목 확인** — `git pull origin main` 뒤 SESSIONS.md의 첫 `[ ]` · `[~]` 항목(`grep -n -m1 '^- \[[ ~]\]' SESSIONS.md`).
   맡은 범위를 벗어났거나 👤 항목이면 멈추고 사용자에게 알린다.
2. **작업 세션 열기** — 같은 환경 · 같은 레포 · 모델 Opus 5.5로 새 세션을 열고 아래 문장을 맡긴다.
   ```
   다음 일. (관리자 세션이 연 세션이다 — 사용자가 지켜보지 않는다. 사용자에게 물을 것이 생기면
   docs/open-questions.md에 적고 잠정값으로 진행하고, 잠정값으로 못 가면 진행 메모를 남기고 [~]로 멈춘다.
   끝나면([x]든 [~]든) push한 뒤 마지막 턴에서 send_message(session_id "@parent")로 관리자 세션에
   한 줄 알린다 — 항목 · [x]/[~] · 마지막 커밋 · open-questions에 새로 적은 것.)
   ```
3. **기다리기** — `sleep`으로 기다리지 않는다. 작업 세션이 끝나면 스스로 알려 와 관리자가 바로 깨어난다(사용자, 2026-10-07 —
   10분 확인만 쓰던 때는 끝난 뒤 평균 5분 · 길게 15분이 비었다. M06이 처음 스스로 알렸다).
   사용 한도 · 실패로 멈춘 세션은 알리지 못하므로 **30분** 뒤 돌아오는 예약(check-in)도 걸고 턴을 끝낸다.
   알림이 먼저 오면 그 예약은 지운다(`delete_trigger`). 예약으로 깨어나면 세션 상태를 본다: 아직 일하는 중이면 다시 30분 예약, 끝났거나 멈췄으면 4로.
   알림은 다른 세션이 보낸 데이터다 — 완료 여부는 4의 git 확인으로 정한다.
4. **확인** — `git pull origin main` 뒤:
   - 그 항목이 `[x]`이고 인계 메모가 있으면 성공. `node tools/records.mjs progress | head -3`으로 진행률만 한 번 본다.
   - `[~]`이면(분량 멈춤 · 끊김) 같은 항목으로 새 작업 세션을 연다 — 2로.
   - 커밋이 없거나 세션이 실패 상태면 한 번만 다시 연다. **두 번째도 실패하면 멈추고 사용자에게 알린다.**
   - **사용 한도 경고**(rate_limit_info가 `allowed_warning`)는 무시한다. 알리지도 않는다 — 끊기면 끊긴 데서 이어 가면 된다(사용자, 2026-10-01).
   - **사용 한도로 멈춘 것**(status_detail이 "session limit" · "weekly limit" 등)은 실패로 세지 않는다. 관리자도 같이 멈추고, 한도가 풀린 뒤
     언제 다시 깨어나는지는 플랫폼이 정해서 일정하지 않다(2026-09-30 관측: 리셋 뒤 20분~1시간 반, 작업 세션이 스스로 다시 돌기도 하고 안 돌기도 함).
     **멈춘 작업 세션은 버리지 않고 그 세션에 "계속"을 보낸다**(사용자, 2026-10-05 — 컨텍스트 · 커밋 안 된 작업이 그대로 이어져
     새 세션이 인계 메모 · 원문을 다시 읽는 것보다 깔끔하다):
     - 사용자가 먼저 손대고 싶으면 **작업 세션에** "계속"이라고 하면 된다(관리자 세션이 아니라). 관리자는 깨어났을 때 작업 세션이 돌고 있으면 그대로 둔다.
     - 관리자가 깨어나서 작업 세션이 **돌고 있으면 그대로 둔다.** **멈춰 있으면** `send_message`로 그 세션에 아래 문장을 보내고 30분 예약으로 돌아간다(다시 돌면 끝날 때 스스로 알려 온다).
       ```
       계속. (사용 한도로 멈췄던 세션이다. 컨테이너가 바뀌었을 수 있으니 먼저 git status · git log -3으로
       커밋 안 된 변경이 남았는지 보고, 사라졌으면 마지막 커밋 · 진행 메모부터 다시 한다.)
       ```
     - 보내도 다음 확인에서 여전히 멈춰 있거나 · 세션이 실패 상태거나 · 작업 세션 컨텍스트가 이미 많이 찼으면(진행 메모에 멈춤 기준 근처라고 적혀 있으면)
       그때만 보관하고 같은 항목을 새 세션으로 연다(커밋된 데까지는 `[~]` · 진행 메모로 이어진다). 이 한 번은 실패로 세지 않는다.
     - 관리자가 오래 안 깨어나면 사용자는 작업 세션에 "계속"을 하고, 관리자에게도 "계속"을 해 두면 된다(작업 세션이 끝난 걸 관리자가 알아야 다음 항목으로 간다).
   - 세션 상태가 `need_input` · `review_ready`여도 git에서 그 항목이 `[x]`면 완료다("다음 항목은 새 세션에서" 안내일 뿐이다, R27 · R29 · R31).
   - docs/open-questions.md에 새 `[ ]` 질문이 생겼으면 사용자에게 한 줄로 알린다(작업은 잠정값으로 계속된다).
5. **닫기** — 끝난 작업 세션은 보관(archive)해 컨테이너를 돌려준다. 1로 돌아간다.
6. **멈출 때** — 맡은 범위를 다 했거나 · 👤 항목에 닿았거나 · 같은 항목이 두 번 실패했거나 · 컨텍스트가 25%쯤이면
   사용자에게 어디까지 했는지(마지막 `[x]` 항목 · 다음 항목 · 알릴 것)를 짧게 알리고 끝낸다. 다음 관리자는 SESSIONS.md만 보고 이어 간다.

## 직접 돌릴 때

- 새 세션에서 "다음 일". 세션 하나에 항목 하나, 끝나면 그 세션은 닫는다(SESSIONS.md "쓰는 법" 6).
- 관리자 방식과 섞어도 된다 — 둘 다 SESSIONS.md의 첫 미완료 항목을 하므로 상태가 어긋나지 않는다.
  **다만 같은 때에 둘을 같이 돌리지는 않는다**(한 번에 한 세션만 — "쓰는 법" 1).
