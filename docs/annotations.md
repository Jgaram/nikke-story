# 주석 기록 — 1회독 형식 · 규칙 (A3) · 떡밥 줄기 (B0b) · 층 · 중요도 판정 (B0b-2 · X3) · 주역 명단 (X3f) · 마무리 기록 (X3f-1d) · 합류 기록 (X3f-1g) · 2회독 기록 (B1a) · 2회독 인계 · 볼 거리 (B1b) · 작중 연대기 (X1b · X1c) · 팬용 문장 (W14) · 시점별 판 (W15c)

원문을 읽으며 남기는 기록의 형식과 규칙. **1회독(줄거리 층)** 은 아래 "1회독 기록 쓰는 법"부터, **2회독(대사 층 — 암시 언급 · 떡밥 암시 · 재언급 · 인물 변화 · 생활상 · 1회독 바로잡기)** 은
"2회독 기록"(B1a)에, 2회독 세션이 먼저 읽는 인계 파일과 1회독이 넘긴 볼 거리는 "2회독 인계 파일"(B1b)에 있다. 왜 두 번 읽는지는 TODO.md 결정 #8, 세션 순서와 인계는 [docs/history/reading.md](history/reading.md).

- 해석이 필요한 기록(밝혀진 사실 · 던져진 의문 · 회수 · 작중 시점 · 정체 연결)은 **후보**다. Claude가 근거 · 이유 · 확신도와 함께 남기고,
  확정 전 후보를 결과에 확정값처럼 쓰지 않는다. **후보는 Claude가 단위마다 스스로 검토해 확정 · 기각한다** — 1회독(사용자, RV1 2026-09-29)도 2회독(사용자, 2026-09-29)도.
  사용자는 기준에 피드백을 주고, Claude가 기준을 고쳐 다시 판정한다(CLAUDE.md "일하는 법").
- 해석 · 판정은 원문 기록만 보고 한다(CLAUDE.md).
- 도구: `node tools/records.mjs` — 뼈대 만들기 · 검증기 · 리뷰 도구 · 진행률 · 인계 파일. 원문은 `node tools/read.mjs <키> --num`.

## 1회독 기록 쓰는 법 (읽기 세션 R · RE)

1. **시작** — 인계 파일의 "먼저 읽을 것"을 읽는다: `annotations/read1/HANDOFF.md`(진행 위치 · 다음 번호 · 되짚기 메모) +
   `handoff/questions-*.md`(열린 의문 — 2만 자를 넘어 나뉨, HANDOFF.md 표에 나온다) · `recent.md`(직전 세션 사실) · `focus.md`(이번 항목 원문에 나오는 대상의 앞 사실). 그 밖의 앞 사실은
   `node tools/records.mjs find <이름>` · `handoff/facts*.md`, 앞 세션의 단위 요약은 `handoff/<세션>.md`에서 필요한 것만 연다(아래 "인계 파일").
2. **단위마다** (읽기 순서 항목에 적힌 순서대로. 서브퀘스트는 씬 하나 `sub:칠리페퍼_00`이 한 단위다)
   1. `node tools/read.mjs ch00 --num` — 파트를 전부 읽는다(`--part 2` …). **`--num`을 꼭 붙인다** — 줄마다 `#N`이 붙고, 근거는 이 번호로 쓴다.
   2. `node tools/records.mjs new ch00` — 뼈대 `annotations/read1/ch00.json`이 생긴다(세션은 읽기 순서에서 찾아 넣는다).
      씬이 여럿이면 씬 한 줄 요약 자리가 들어 있다 — 채우거나 `scenes`째 지운다.
   3. 파일을 채운다: `summary` · 사실 · 의문 · 사건(앞 사실 · 의문에 일어난 일) · 시점 · 새 대상 · 되짚기 메모. 형식은 아래 "파일 형식".
      번호는 `node tools/records.mjs next`(사건은 `next F12`), 이미 있는 사실인지는 `node tools/records.mjs find <낱말>`.
   4. 새 대상이 있으면 사전에 먼저 더한다(아래 "새 대상과 사전") → `node --test`.
   5. `node tools/records.mjs check` — 오류 0이 될 때까지 고친다. 경고는 읽고 괜찮으면 둔다.
   6. `node tools/records.mjs handoff` — 인계 파일을 다시 만든다(`node --test`가 인계 파일이 오래됐으면 실패한다).
   7. 커밋 · push하고 SESSIONS.md 항목 아래 진행 메모를 고친다(`진행: ch02까지 완료, sub:칠리페퍼_00부터`).
3. **끝** — SESSIONS.md 완료 · 인계 메모. 형식을 쓰며 불편했던 점은 인계 메모에 적는다(1회독 형식 메모는 B1a가 반영했다).

한 파일은 한 세션이 쓴다. 읽기 세션은 **자기 단위 파일만** 만들고 고친다 — 앞 단위에서 잘못을 찾으면 되짚기 메모(`revisit`)로 남기고
리뷰(RV)에서 고친다. 2회독의 1회독 바로잡기만 예외다(아래 "1회독 바로잡기"). 상태(`status`) · 검토 기록(`reviews`)은 손으로 바꾸지 않는다 — 리뷰 도구만 바꾼다.

## 무엇을 남기나 — 1회독 (줄거리 층)

드러난 것만 남긴다. 행동 · 묘사로 흘린 복선과 암시는 2회독 몫이다(결정 #8) — 검증기가 `암시`를 막는다.

| 기록 | 칸 | 후보인가 | 무엇 |
|---|---|---|---|
| 단위 요약 | `summary` · `scenes` | 아니다 — 작업 메모 | 다음 세션이 원문 대신 읽는 줄거리. 그대로 공개하지 않고, 사이트에 싣는 **공개 개요**(아래 "공개 개요")의 입력으로 쓴다(사용자, 2026-10-10) |
| 밝혀진 사실 | `facts` (정의) · `events`(`드러냄` · `뒤집음`) | 후보 | 진실 공개 후보 — 독자가 새로 알게 된 사실 |
| 던져진 의문 | `questions` (정의) · `events`(`회수`) | 후보 | 떡밥 제기 후보 — 이야기가 독자에게 던진 물음과, 그것이 드러내 놓고 풀린 곳(회수, Q-A3-2) |
| 작중 시점 | `times` | 후보 | 기준점("CH.20 직후", "70년 전")과 회상 구간 |
| 새 대상 | `targets` | 아니다 — 사전이 정한다 | 이 단위에서 처음 나온 인물 · 장소 · 조직 … (사전 ID) |
| 되짚기 메모 | `revisit` · `revisitDone` | 아니다 | 다음 세션에 넘기는 "되짚기 필요: 무엇 · 어디" |
| 정체 연결 | `annotations/dictionary/people.json` `candidates` | 후보 | 같은 인물로 드러남(모나 = 모르가나). A1 형식 그대로 |

- **사실은 씬별로 "드러냄 / 뒤집음"만 적고 단계는 적지 않는다**(결정 #8). 처음 밝혀짐 · 보강 · 뒤집힘 같은 단계는 읽는 순서(출시 순이든
  메인 우선이든)를 정한 뒤 계산한다. 그래서 사실 정의가 든 파일이 "처음 밝혀진 곳"이라는 뜻이 아니다 — 처음 **기록한** 곳일 뿐이다.
- 한 기록 = 한 씬이 원칙이다. 다른 씬에서 또 드러나면 사건(`F12-2`)을 따로 적는다. 근거의 첫 씬이 그 기록의 씬이다.
- 사실 문장은 한 문장, 의문은 물음표로 끝나는 한 문장. 인계 목록에 한 줄로 들어가므로 200자 안쪽(넘으면 경고).
- **설정 오류**(사용자, 2026-09-29): 라이브 업데이트 게임이라 원문끼리 어긋나거나(숫자 · 날짜 · 누가 무엇을 했는지) 설정이 흐지부지 사라지기도 한다.
  일부러 찾아 모으지는 않는다. 읽다가 헷갈리는 곳이 제작 쪽 실수로 보이면 기록 파일 `slips`에 한 줄 남기고 넘어간다 —
  무엇과 무엇이 어긋나는지 · 근거(씬 ID `#N`, 앞 사실이면 그 ID) · 어느 쪽을 따르는지. 예: `"F40(ch07 #12, 3년 전)과 어긋남 — 여기선 5년 전(d_main_20_03 #41). 설정 오류로 보고 F40을 따른다"`.
  뒤집음(`F-k`) · 의문으로 세우지 않고, 확인하려고 되짚어 읽지 않고, 사용자에게 묻지 않는다. 이야기 안에서 뜻이 있는 모순(거짓말 · 착각 · 기억 조작 등)으로
  보이면 설정 오류가 아니라 평소대로 사실 · 뒤집음 · 의문으로 적는다 — 판단이 안 서면 설정 오류 쪽에 "추정"이라 쓰고 넘어간다. 인계 파일 세션 요약에 "설정 오류 추정"으로 나온다.
- 얼마나 잘게 쪼갤지 · 확실/추정 경계는 R01 수준 그대로다(사용자가 RV1에서 적절하다고 함 — docs/history/reading.md RV1 인계).

| `tests/fixtures/read1/` · `read2/` | **예시** — 형식을 보이는 고정 파일(`_people.json` · `_threads.json` · `_layers.json` · `_leads.json` · `_closures.json` · `_links.json` · `_watch.json`은 read1/ 안). 실제 기록 · 진행률 · 인계 파일에 섞이지 않는다 | 테스트 |

- 파일 이름 = 키의 `:`를 `.`으로: `ch00.json` · `sub.칠리페퍼_00.json` · `fl.b-side_idol.json` · `d_ex_elevator_01.json`.
  파트를 세션에 나눠 읽는 단위(`event_staranis1` 파트 1–3 / 4–6)는 `parts`를 적고 첫 파트를 붙인다: `event_staranis1.p1.json` · `event_staranis1.p4.json`.
- 1회독 기록은 **DB 빌드 입력이 아니다** — 도구가 JSON을 바로 읽는다. 그래서 기록을 고쳐도 DB를 다시 만들지 않는다
  (`tools/normalize/ensure-db.mjs`가 `annotations/read1/`을 지문에서 뺀다). people.json은 빌드 입력이다(`target_links`).
- 이름이 `_`로 시작하는 JSON은 기록 파일로 읽지 않는다.

**파일 칸**

| 칸 | 필수 | 뜻 |
|---|---|---|
| `unit` | ✓ | 읽기 단위 키 — read.mjs 키 그대로(`ch00` · `event_…` · `fl:…` · `side:…` · 씬 키 `sub:…_00` · `d_ex_elevator_01`). 범위 안이어야 한다 |
| `parts` | | 단위를 세션에 나눠 읽을 때만 `"4-6"` |
| `session` | ✓ | 순서 항목(`R01` · `RE32`). 읽기 순서와 다르면 경고 |
| `by` | ✓ | 기록자 — 언제나 `"claude"`. 후보마다 `by`를 따로 쓰면 그것이 이긴다 |
| `date` | | 기록한 날 `YYYY-MM-DD` |
| `summary` | ✓ | 단위 요약(작업 메모 — 공개 개요의 입력). 줄거리 · 누가 무엇을 · 중요한 씬 ID. 1,500자 안쪽(넘으면 경고) — 챕터 하나에 300–1,000자 |
| `scenes` | | 씬 한 줄 요약 `[{scene, text}]` — 되짚어 읽을 씬을 찾는 데 쓴다. 씬이 여럿인 단위에 권한다. 150자 안쪽 |
| `facts` · `questions` · `events` · `times` · `targets` · `revisit` · `revisitDone` | | 배열 (아래) |
| `slips` | | 설정 오류 추정 — 문장 배열, 한 줄에 하나(300자 안쪽). 아래 "설정 오류" |
| `note` · `_comment` | | 자유 메모 |

**후보 공통 칸** — `facts` · `questions` · `events` · `times`의 항목, people.json의 정체 연결 후보

| 칸 | 필수 | 뜻 |
|---|---|---|
| `id` | ✓ | 후보 ID (아래 "ID") |
| `evidence` | ✓ | 근거 `[{ "scene": 씬 ID, "lines": [줄 번호 …] }]` (아래 "근거"). 정체 연결은 비어도 된다(1회독이 채운다) |
| `reason` | ✓ | 이유 — 왜 이렇게 읽었나. 근거 줄을 짧게 인용해도 된다 |
| `confidence` | ✓ | 확신도 `확실` · `추정` |
| `status` | ✓ | 상태 `후보` · `확정` · `기각`. 새로 쓸 때는 늘 `후보` |
| `by` | (파일) | 기록자. 없으면 파일의 `by` |
| `about` | | 이 기록이 다루는 대상 ID 배열(`person:라피` · `place:방주` …) — 사전에 있어야 한다 |
| `note` | | 메모 |
| `reviews` | | 검토 기록 — **리뷰 도구가 붙인다**(아래 "상태 · 검토") |

**종류별 칸**

| 종류 | ID | 더 있는 칸 |
|---|---|---|
| 사실 정의 `facts` | `F<n>` | `text`(사실 한 문장, 필수). 정의 = 처음 기록한 드러냄. `act`는 쓰지 않는다 |
| 의문 정의 `questions` | `Q<n>` | `text`(물음 한 문장, 필수). 정의 = 제기 |
| 사실의 사건 `events` | `F<n>-<k>` (k ≥ 2) | `act`: `드러냄`(다시 드러남 — 보강인지는 계산한다) · `뒤집음`(앞서 드러난 사실이 틀렸거나 바뀜). 뒤집음은 새 진실을 새 사실로 세우고 `replacedBy`로 잇는다. `text`(이번에 드러난 것, 선택) |
| 의문의 사건 `events` | `Q<n>-<k>` (k ≥ 2) | `act`: `회수` · `answer`(답이 된 사실 ID, 필수) · `degree`: `전부` · `일부` |
| 작중 시점 `times` | `S<n>` | `kind`: `기준점`(이 씬이 언제인가 — "CH.20 직후", "갓데스 폴 70년 뒤") · `회상`(과거 장면 구간 — 근거를 그 구간으로). `text`(필수) · `ref`(기준이 되는 단위 키 · 씬 ID · 대상 ID · 후보 ID, 선택) · `at`(관계 · 기준 — 필수, 없으면 `[]`) · `subject` · `years`(선택) — 아래 "작중 연대기" |
| 새 대상 `targets` | — | `target`(사전 대상 ID, 필수) · `evidence`(처음 나온 줄) · `note`(누구 · 무엇인지 한 줄, 필수) · `new`(이 세션에서 사전에 새로 더했으면 `true`) |
| 되짚기 `revisit` | `V<n>` | `text`(무엇 · 어디, 필수) · `where`(씬 ID · 단위 키 배열). 닫을 때는 뒤 단위 파일의 `revisitDone`에 `{id, note}` |

- 드러냄과 회수를 같은 씬에서 함께 적어도 된다 — 사실 `F7`(드러냄)과 `Q3-2`(회수, `answer: F7`)는 따로 검토받는다.
- 앞 단위의 사실 · 의문에 일이 생기면 **지금 단위 파일의 `events`**에 적는다(앞 파일은 고치지 않는다).
- 모르는 칸은 경고가 뜬다(오타 잡기).

## 근거 — 씬 ID와 줄 번호

- `scene`은 씬 ID다. 블라링크는 게임 씬 ID(`d_main_01_01_s` · `event_nocallerid_01_s` · 호감도 스토리 `ep:…`), 금서고는 씬 키
  (`sub:로망티스트_00` · `side:mudfish_03` · `fl:absolute_03` — 금서고 파일 안 순서이고 게임 씬 ID가 아니다). read.mjs 씬 머리줄(`## …`)에 나온 그대로다.
- `lines`는 **줄 번호 = DB `lines.seq`** — 씬 안에서 0부터, 빈틈없이 이어진다. `read.mjs --num`이 줄 앞에 붙이는 `#N`, 이동 표시 `→#N`,
  `query.mjs search` 결과의 `(씬 ID#N)`, `query.mjs story`의 줄 앞 번호가 모두 같은 번호다(블라링크 · 금서고 똑같다 — `tests/records.test.mjs`가 확인한다).
  금서고 원본 파일의 줄 번호(빌드 경고의 "원문 1955줄")와는 다르다.
- 숫자 하나는 한 줄, `"a-b"` 문자열은 a부터 b까지(둘 다 포함): `"lines": [12, 13, "20-25"]`. 400줄 넘는 범위는 씬을 나눠 적는다.
- 인용 표기는 `씬#줄`: `d_ex_elevator_01#22-27,31-32`. 리뷰 도구 · 인계 파일이 이렇게 보여 준다.
- 근거가 이 파일의 단위 밖 씬이면 경고가 뜬다 — 되짚어 읽기로 찾은 것이면 `note`에 적어 둔다.
- 본문 없는 줄(범위 안 18줄)을 가리키면 경고.

- **한 번 붙인 ID는 바꾸지 않는다** — 다른 기록 · 2회독 · 분석이 ID로 가리킨다. 문장을 고쳐도 ID는 그대로다.
- 다음 번호: `node tools/records.mjs next` · `next F12`. 인계 파일(HANDOFF.md)에도 적혀 있다. 세션은 한 번에 하나만 도므로 겹치지 않는다(겹치면 검증기가 잡는다).
  2회독도 같은 데이터셋이라 `F` · `Q` · `S` · `V`는 1회독 번호를 이어 쓴다(바로잡기로 더하는 사실 · 의문 · 시점, 2회독 되짚기 메모).
- ID 접두는 세션 이름(R · P · M · B · C · X · W · N · H · A)과 겹치지 않게 골랐다 — `review P1`이 세션인지 기록인지 헷갈리지 않는다.
- 채팅에서도 이 ID로 말한다: "F3 · F5 확정, Q2-2 기각".

## 새 대상과 사전

대상의 정의(ID · 표준명 · 별칭 · 갈래)는 **사전**(`annotations/dictionary/`, A1 · A2 — docs/schema.md "대상 ID" · "비인물 사전")에만 있다.
1회독 기록의 `targets`는 "이 단위에서 처음 나왔다"는 기록과 누구 · 무엇인지 한 줄 메모이고, 사전 ID로만 가리킨다.

1. 원문에서 새 이름을 보면 사전에 있는지 본다: `node tools/query.mjs who <이름>`.
2. 없으면 표기를 실측하고(`node tools/query.mjs search <표기>`) 사전 파일에 더한다 — 인물은 people.json `persons`(이름표가 있는 인물은
   이미 speakers.json에서 만들어져 있다), 비인물은 종류별 파일. `node --test`(0건 표기면 실패).
3. 기록 파일 `targets`에 `{ "target": ID, "evidence": [처음 나온 줄], "note": "누구 · 무엇", "new": true }`.
   사전에 이미 있던 대상이 이 단위에서 처음 소개되면 `new: false`로 적는다 — 줄거리에 중요한 것만(첫 등장 전체는 B2가 자동으로 센다, Q-A3-3).
4. 정체가 드러나는 연결(묘사형 이름표 = 이름 있는 인물 등)은 people.json `candidates`에 다음 `L` 번호로 후보를 더한다. 근거가 비어 있는
   A1 후보(L1 모더니아 ↔ 마리안 등)는 드러나는 씬을 읽을 때 `evidence`를 채운다.

검증기는 `targets` · `about` · `ref`의 대상 ID가 사전(DB `targets`)에 없으면 오류를 낸다. 한 대상을 두 단위에서 새 대상으로 적으면 경고.

## 상태 · 검토

- 상태는 `후보` → `확정` 또는 `기각`. 1회독은 Claude가 단위를 기록한 뒤 스스로 검토해 `set <단위> 확정 --by claude --session R02`로 적는다
  (틀리거나 불필요한 것은 먼저 `기각` · `--text`로 고쳐 확정, 판단이 안 서는 것은 `보류` 대신 추정으로 확정하고 이유에 적는다).
  2회독 해석 기록도 같다(`--session M03` 등). 사용자가 채팅으로 피드백을 주면 기준(이 문서 · 판정 카드)을 먼저 고치고 그 기준으로 Claude가 다시 판정한다.
- 결정 = `확정` · `기각` · `보류`(미룸 — 상태는 후보 그대로, 다음 리뷰에서 먼저 보인다) · `후보`(되돌리기).
- 결정마다 `reviews`에 한 줄이 붙는다: `{ "decision", "by"(결정한 쪽 — 언제나 "claude"), "date", "session"(RV1 …), "note", "before"(문장을 고쳤으면 고치기 전) }`.
  `status`는 검토 기록의 결과와 같아야 한다(검증기) — 손으로 `확정`을 쓰면 오류다.
- 기각된 사실 · 의문을 가리키는 기록(사건 · 회수의 `answer` · 시점의 `ref`)이 후보나 확정으로 남으면 오류다 — 같이 기각하거나 다른 것으로 옮긴다.
  `set`이 기각한 뒤 그런 기록을 바로 알려 준다.
- 인계 파일 · 결과에는 기각된 것을 넣지 않는다. 확정 전 후보는 `✓` 없이 보인다 — 결과로 쓰지 않는다.

## 검증기 — `node tools/records.mjs check`

오류(종료 코드 1): 없는 씬 ID · 줄 번호 · 범위 밖 씬, 상태 · 확신도 · 결정 · `act` · `degree` · `kind` 값 오타, 필수 칸 누락(`unit` · `session` ·
`by` · `summary` · `text` · `evidence` · `reason` …), ID 모양 · 겹침, 없는 사실 · 의문 · 대상 · 되짚기 메모를 가리키는 참조,
기각된 것을 가리키는 참조, 검토 기록과 어긋난 상태, 파일 이름과 `unit`이 어긋남, 1회독 파일의 `암시`(2회독 파일 echoes 몫).
줄 번호 하나를 문자열(`"12"`)로 쓰면 오류에 "줄 하나는 숫자로(12), 범위만 문자열("20-25")"을 붙인다(1회독 형식 메모 — 뼈대 `_comment`에도 예가 있다).
경고: 모르는 칸, 단위 밖 씬을 근거로 듦, 본문 없는 줄, 긴 요약 · 문장, 읽기 순서와 다른 세션, 두 번 적은 새 대상 · 닫기.
2회독 기록 · 바로잡기 · 수동 엣지의 검사는 아래 "2회독 기록" · "1회독 바로잡기".
끝에 인계 파일이 최신인지와 "먼저 읽을 것" 크기를 알려 준다. `node --test`(`tests/records.test.mjs`)도 같은 검사를 하고, 인계 파일이 오래됐으면 실패한다.

## 떡밥 줄기 — `annotations/threads.json` (B0b)

의문 · 사실은 그래프에 올리기엔 잘다. **같은 수수께끼를 다루는 의문 · 사실을 줄기로 묶는다** — 시각화 화면 3(떡밥 하나가 풀려 온 흐름) ·
화면 4(떡밥끼리의 관계)의 노드이고, 화면 1(중요도)의 판정 입력이다(docs/views.md). 줄기 · 관계 · 중요도는 해석이라 후보로 쓰고 Claude가 확정한다
(CLAUDE.md "해석이 필요한 기록"). 사용자는 기준에 피드백을 준다(CLAUDE.md "일하는 법").

```json
{
  "session": "B0b", "by": "claude", "date": "2026-10-04",
  "threads": [
    { "id": "J1", "title": "마리안 — 침식 · 모더니아 · 여왕의 각성", "text": "마리안은 누가 언제 침식시켰고 … — 지휘관과는 무엇으로 이어져 있나",
      "weight": "뼈대", "questions": ["Q1", "Q20", "…"], "facts": [], "about": ["person:마리안", "person:모더니아"],
      "reason": "왜 이 중요도인가 — 근거 기록 ID", "confidence": "확실", "status": "후보" }
  ],
  "relations": [
    { "id": "G1", "type": "같은 진실", "a": "J4", "b": "J5", "text": "언체인드는 갓데스의 지휘관 — 엔더슨 — 의 피에서 나온다",
      "evidence": ["F682", "F2363", "F2373"], "reason": "…", "confidence": "확실", "status": "후보" }
  ]
}
```

예시: [tests/fixtures/read1/_threads.json](../tests/fixtures/read1/_threads.json) (예시 디렉터리에서는 `_threads.json`).

| 칸 | 필수 | 뜻 |
|---|---|---|
| `id` | ✓ | 줄기 `J<n>` · 관계 `G<n>` — 한 번 붙이면 바꾸지 않는다(2회독 기록 · 분석이 가리킨다) |
| `title` | ✓(줄기) | 짧은 이름 — 화면 라벨 |
| `text` | ✓(줄기) | 이 줄기가 다루는 수수께끼 한 문장(200자 안쪽). 관계는 선택 — 두 줄기가 어떻게 이어지는지 |
| `weight` | ✓(줄기) | 중요도 — 아래 |
| `questions` | | 든 의문 정의 ID. **의문 하나는 줄기 하나** — 가까운 줄기는 관계로 잇는다. 기각되지 않은 의문은 모두 어느 줄기에 든다(빠지면 경고) |
| `facts` | | 의문에 안 걸렸지만 줄기에 꼭 넣을 사실 정의 ID(드물게). 의문의 답은 적지 않아도 계산으로 든다 |
| `about` | | 줄기가 다루는 대상 — 그 줄기만의 대상으로 고른다. 지휘관 · 방주 · 니케 · 랩쳐처럼 어디에나 걸리는 대상은 넣지 않는다 |
| `type` · `a` · `b` | ✓(관계) | 관계 종류(아래)와 두 줄기 |
| `evidence` | ✓(관계) | 관계를 보여 주는 기록 ID 배열(`F12` · `Q3-2` …) — 씬 줄이 아니라 기록이다. 줄기 자체는 `questions`가 근거다 |
| `reason` · `confidence` · `status` · `reviews` · `by` · `note` | | 후보 공통 칸과 같다 |

**중요도(`weight`)** — 메인 · 세계관을 이해하는 데 그 수수께끼가 얼마나 무거운가(docs/views.md 화면 1의 기준을 줄기에 쓴 것):
- `뼈대` — 메인 전체를 꿰는 수수께끼: 세계관의 근본(랩쳐 · 헬레틱 · 퀸 · 니케 · 방주 체제)이거나 메인 주역(지휘관 · 라피 · 마리안 · 엔더슨 · 도로시)의 정체,
  또는 여러 챕터 묶음에 걸쳐 메인이 거듭 돌아오는 것.
- `보강` — 메인 한 아크의 수수께끼(메인 안에서 풀린다) · 메인 인물의 배경 · 메인 사건의 앞뒤 사정. 알면 메인이 깊어지지만 메인 줄거리는 따라간다.
  메인에서 던졌지만 아직 하나도 안 풀려 무게를 모르는 것도 여기 둔다(뒤에서 무거워질 수 있다 — `confidence: 추정`).
- `독립` — 서브퀘스트 · 유실물 · 이벤트 · 호감도 안에서 던지고 끝나는 이야기.
- 중요도는 줄기의 무게다. 단위의 등급(필수 · 보강 · 독립)은 단위의 가장 묵직한 기록 한 건으로 따로 정한다(B0b 층 나누기 · X3) —
  뼈대 줄기에 든 단위라도 그 단위가 준 것이 곁가지 사실뿐이면 보강이다.

**관계(`type`)** — 한 쌍에는 가장 강한 관계 하나(겹치면 경고):
- `원인` — a의 진실이 b의 일을 일으켰거나 설명한다(a → b). 예: 에닉의 거래(J16) → 마리안의 침식(J1).
- `포함` — b는 a의 한 갈래다(a ⊃ b). 예: 에덴(J8) ⊃ 에덴의 필그림(J29).
- `같은 진실` — 한 진실의 두 면, 근거가 두 줄기의 답을 함께 준다(방향 없음). 예: 언체인드(J4) = 갓데스의 지휘관의 피(J5).
- `맞물림` — 두 줄기의 인물 · 사건이 근거 기록에서 만난다. 원인 · 같은 진실이라 할 만큼은 아니다(방향 없음).

**소속 계산**(`tools/records/threads.mjs`, 기록하지 않는다 — 같은 기록이면 같은 결과):
- 의문 → 그 회수(`Q<n>-k`) → 답(`answer`)이 된 사실 → 그 사실의 드러냄 · 뒤집음과 뒤집음의 새 사실(`replacedBy`)이 곧바로 든다. `facts`도 곧바로 든다.
  한 사실이 두 줄기 의문의 답이면 둘 다에 든다.
- `about`이 겹치는 사실 정의는 "about으로 든 사실"이다 — 여러 줄기에 들 수 있고, 화면 3에서 흐리게 · 층 나누기에서 참고로만 쓴다.
- 기각된 기록 · 줄기는 뺀다. 결과는 시안 `data/views/read1/threads.csv`(줄기별)와 `units.csv`의 `threads`(단위의 기록이 든 줄기 `J1:q2e1f1` —
  의문 정의 · 사건 · 곧바로 든 사실 정의 수) · `thread_weight`(그중 가장 무거운 중요도)에 나온다(`node tools/views/draft.mjs`).

**고치는 법**
- 새 의문이 생기면(2회독 바로잡기 · 신작 N3) 그 의문을 어느 줄기의 `questions`에 넣거나 새 줄기(다음 `J` 번호, `records.mjs next`)를 세운다 — 검증기가 빠진 의문을 경고한다.
- 줄기 파일은 한 번에 한 세션이 고친다. 상태 · 검토 기록은 리뷰 도구로만 바꾼다(`set J3 확정 --by claude --session B0b`).
  기각된 의문을 든 줄기, 기각된 줄기를 잇는 관계는 오류다 — 같이 고치거나 기각한다.
- 줄기 파일은 DB 빌드 입력이 아니다(1회독 기록처럼 도구가 바로 읽는다 — `ensure-db.mjs` 지문에서 뺀다).

## 층 판정 — `annotations/layers.json` (B0b-2)

2회독은 층별로 읽는다(사용자, 2026-10-04 — docs/history/reading.md P · M). 층은 **메인 밖 단위의 등급**(중요도의 첫 시안, docs/views.md 화면 1)과 단위 종류로 정한다.
등급은 해석이라 후보로 쓰고 Claude가 확정한다(CLAUDE.md "해석이 필요한 기록"). 사용자는 기준에 피드백을 주고, 기준이 바뀌면 Claude가 다시 판정한다.

```json
{
  "session": "B0b-2", "by": "claude", "date": "2026-10-04",
  "units": [
    { "id": "K118", "unit": "event_overzone", "grade": "필수", "basis": "Q105-2",
      "reason": "메인 ch19 의문(에덴의 도로시는 누구인가)의 답 — …", "confidence": "확실", "asof": "2026-09-24", "status": "확정", "reviews": [ … ] }
  ]
}
```

예시: [tests/fixtures/read1/_layers.json](../tests/fixtures/read1/_layers.json) (예시 디렉터리에서는 `_layers.json`).

| 칸 | 필수 | 뜻 |
|---|---|---|
| `id` | ✓ | `K<n>` — 한 번 붙이면 바꾸지 않는다 |
| `unit` | ✓ | 판정하는 읽기 단위(docs/history/reading.md R 순서의 키). 메인은 채점하지 않아 넣지 않는다. 단위 하나에 판정 하나(틀린 것은 기각하고 새로) |
| `grade` | ✓ | 등급 — 아래(X3f부터 넷: 필수 · 보강 · 참고 · 독립) |
| `basis` | 필수 · 보강 ✓ | 등급을 정한 **한 건** — 이 단위의 사실 · 의문 · 사건 ID(`Q105-2` · `F768-2`), 드물게 줄기 ID(`J12`). 참고는 메인이 말하지 않은 기록 하나, 독립은 걸린 독립 줄기나 대표 기록, 없으면 비운다 |
| `from` · `before` | 필수 · 보강 (X3f) | 메인이 이 단위를 딛기 시작하는 챕터(`ch38`)와 그 앞 자리의 등급(더 가벼운 등급) — 아래 "중요도 판정" X3f ⑤. 단위가 그 챕터보다 뒤에 나왔으면 `before`는 없어도 된다 |
| `layer` | | 규칙 층을 뒤집을 때만(1 · 2 · 3) — note에 까닭. 등급은 그대로 두고 읽는 차례만 바꿀 때, 2회독 뒤 등급을 바꿔 읽은 층과 달라질 때(아래 "중요도 판정") |
| `asof` | 확정 ✓ | 기준 시점(X3a) — 판정이 반영한 스토리의 마지막 공개일(YYYY-MM-DD). 없으면 경고 |
| `reason` · `confidence` · `status` · `reviews` · `by` · `note` | | 후보 공통 칸과 같다. reason은 그 한 건이 메인 · 세계관의 무엇에 닿는지(메인 챕터 · 줄기 ID)를 적는다 |

**등급**(docs/views.md 화면 1 — 사용자 기준, 2026-10-04: 메인 · 세계관을 이해하는 데 반드시 알아야 하는가, 합계가 아니라 **가장 묵직한 한 건**):
- `필수` — 그 한 건이 메인(또는 세계관의 뼈대)의 이해를 막는다: 메인이 던진 큰 의문(뼈대 줄기)의 답 · 뒤집음이 여기 있고 메인이 스스로 다시 밝히지 않거나,
  메인이 여기서 처음 드러난 것을 딛고 간다(이 단위의 의문 · 사실을 메인이 회수 · 다시 드러냄 — 뼈대 줄기).
- `보강` — 알면 메인 · 세계관이 깊어진다: 보강 줄기의 의문 · 답, 뼈대 줄기의 곁 의문(메인이 스스로 답한다), 메인 인물의 배경 · 동기,
  메인 사건의 앞뒤 사정, 니케 · 방주 체제 같은 세계관을 자세히 설명함, 아직 열린 뼈대 줄기의 복선.
- `독립` — 메인 · 세계관과 거의 닿지 않는다: 독립 줄기만 걸리거나 줄기가 없고, 메인 대상이 about으로만 스친다(일상극 · 이벤트 안에서 끝나는 이야기).
- 기록 수 · 걸린 줄기 수 · 분량은 등급에 쓰지 않는다. 같은 등급 안 정렬과 판정할 때 훑어보기에만.
- 판정 입력은 `node tools/records.mjs layers <단위 키>`가 보인다 — 메인과 이어진 기록(in · out) · 곧바로 든 줄기 · about으로만 걸친 줄기와 기계 시안.
  시안 규칙은 tools/views/layers.mjs 머리말. 시안은 출발점일 뿐이다 — B0b-2는 432단위 가운데 등급 55(시안 필수 → 보강 17 · 보강 → 독립 28 · 독립 → 보강 7 · 보강 → 필수 3) · 근거 58을 시안과 다르게 골라 확정했다.

**층**(계산 — tools/records/layers.mjs, 같은 판정이면 같은 결과):

| 종류 | 1층 | 2층 | 3층 |
|---|---|---|---|
| 메인 | 전부(채점 없음) | | |
| 서브퀘스트 · 유실물 · 엘리베이터 | 전부 — 챕터와 함께 읽는다(사용자: "1층 = 메인과 딸린 서브퀘스트 · 유실물") | | |
| 사이드 · 이벤트 | 필수 · 보강 ("줄기에 걸린 이벤트 · 사이드") | 참고 · 독립 ("나머지 이벤트") | 독립이면서 1회독 기록 2건 이하(일상극) |
| 이벤트 유실물 | 그 이벤트의 층(필수면 1층) | | |
| 호감도 | 필수 | 보강 · 참고 ("줄기에 걸린 호감도 스토리") | 독립 ("기록이 거의 없는 일상극") |

- 사용자의 층 나눔(2026-10-04, 따옴표)을 그대로 따르고, "줄기에 걸린"을 등급(필수 · 보강)으로 읽었다(Claude, B0b-2) — 독립 줄기만 걸린 단위는 메인 · 세계관과 닿지 않으므로.
  그래서 메인 밖 단위의 층과 등급은 1:1이 아니다: 서브퀘스트 · 유실물은 등급과 상관없이 1층(생활상도 1층에서만 모은다), 보강 이벤트는 1층 · 보강 호감도는 2층.
  등급은 X3 중요도의 첫 시안으로 따로 남는다.
- 층은 2회독의 읽는 차례와 깊이(P · M 머리말 "층마다 하는 것")만 정한다. 화면 1의 등급은 `grade`다.
- 참고(X3f)는 2층이다(Claude, X3f-1) — 메인과 줄로 이어지지 않아 1층("줄기에 걸린")은 아니고, 세계 · 메인 인물을 더 알게 되므로 일상극(3층)도 아니다.
  2회독이 끝나 층은 읽은 층으로 묶였으므로(아래) 이 규칙은 새 단위(N3)와 검증기 경고에만 쓰인다.

**고치는 법**
- 기준이 바뀌어 다시 판정할 때: `set K118 확정 --grade 보강 --note "…"` · 층만: `set K118 확정 --layer 2 --note "…"`(`--by`는 기본 claude). 고치기 전 값은 검토 기록 `before`에 남는다.
- 새 단위(신작 N3 · 순서 추가): `node tools/records.mjs layers --add`가 1회독 기록이 있는데 판정이 없는 단위에 시안(후보)을 더한다 → 단위마다 한 건을 골라 고친 뒤 `set … 확정`.
  검증기가 판정 없는 단위를 경고한다.
- 다시 판정(2회독 · X3 · N3): 판정 객체를 고쳐 쓰지 말고 `set`으로 바꿔 이력을 남긴다 — 아래 "중요도 판정". 단위 하나에 판정 `K` 하나를 끝까지 쓴다(X3a — 근거를 바꿀 때도 `--basis`).
- 층이 바뀌면 docs/history/reading.md M 목록을 다시 뽑는다(`node tools/records/plan.mjs <디렉터리> --layers`) — 이미 읽은 항목은 그대로 두고 남은 것만 고친다.
- 판정 파일은 DB 빌드 입력이 아니다(`ensure-db.mjs` 지문에서 뺀다). 시안 표 `data/views/read1/units.csv`의 `grade` · `layer` · `layer_basis` 칸과 report.md "2회독 층",
  사용자가 훑는 표 `data/views/read1/layers.md`(층 · 종류별로 판정 ID · 등급 · 근거 · 이유)에 나온다(`node tools/views/draft.mjs`).

## 중요도 판정 — 다시 판정 · 기준 시점 · 이력 (X3a)

층 판정의 등급(`grade`)이 화면 1의 중요도다(docs/views.md 화면 1). B0b-2는 1회독 기록으로 판정했고, X3이 2회독 기록을 얹어 다시 판정한다. 신작(N3)마다 또 다시 판정한다.
판정은 해석이라 Claude가 근거 한 건과 함께 확정한다(사용자는 기준에 피드백 — CLAUDE.md "일하는 법").

**척추(X3f-1b · 1c)** — 아래의 "메인"은 모두 **척추**(메인 챕터 + `annotations/spine.json` 확정 단위 — 이벤트 8 · 사이드 3)를 뜻한다. 척추 단위는 판정 입력을 모으지 않고 시안 표에서 빠진다(판정 K는 "척추" 표시로 남는다). 형식은 아래 "척추".

**판정 입력** — `node tools/records.mjs layers <단위 키>`(맨 위에 지금 판정, 그 아래 시안 · 입력 · 기록 문장 6줄, `--read1`이면 1회독만 — B0b-2와 같은 시안). 규칙은 tools/views/layers.mjs 머리말:
- ① 척추와 이어진 기록 — 1회독(바로잡기 포함)의 in · out에 **2회독 떡밥 E**가 더해진다: 이 단위가 흘린 것이 메인에서 드러남(out 암시) · 메인이 이 단위의 것을 다시 꺼냄(out 재언급) ·
  메인이 흘린 것의 답이 여기서 드러남(in 암시) · 메인의 것을 여기서 다시 꺼냄(in 재언급 — 참고만, 시안에 안 쓴다).
- ② 곧바로 든 줄기 — 1회독 기록에 **2회독 떡밥이 가리킨 줄기**가 따로 붙는다(`2회독 떡밥:` 줄). 뼈대 · 보강 줄기 암시는 "아직 열린 줄기의 복선"(보강 쪽), 재언급은 참고.
- ③ about으로만 든 줄기 · 참고 — 줄기 인물(뼈대 · 보강 줄기 `about`의 인물)의 변화 D(기억 · 소속 · 신체 · 신념 — 메인 인물의 배경 · 동기) · 생활상 U 주제별 수.
- ④ 줄기에 안 묶인 사실(X3f — 참고의 문턱) — 어느 줄기에도 곧바로 들지 않은 사실 정의 가운데 세계(조직 · 장소 · 개념 · 사건 · 물건이 about에, 흔한 대상 — 지휘관 · 니케 · 방주 · 중앙 정부 · 카운터스 · 랩쳐 — 빼고)와
  메인 인물(메인 사실 3건 이상에 about으로 든 인물, 지휘관 빼고). 생활상(U)은 2회독 1층에서만 모아 2 · 3층 단위는 이것과 1회독 요약(`--summary`)으로 본다(원문은 다시 읽지 않는다).
- ⑤ 주역 사연(X3f ①) — 주역 명단의 인물을 다룬 사실 2건 이상 · 그 인물의 신념 · 기억 · 소속 · 신체 변화 D. 지휘관은 사실이 어디에나 걸려 변화만 센다.
- ⑥ 뒤 척추 의문(X3f-1c) — 이 단위보다 뒤(읽는 순서)에 척추가 제기한 의문 가운데 이 단위 사실의 about 대상이 겹치는 것(회수 사슬이 잇지 않는 방향 — 카드 3절 4). 어디를 볼지의 단서일 뿐, 판정은 `find`로 문장을 맞댄다.
- ⑦ 빌드업 마무리(X3f-1d) — 척추가 쌓은 것이 여기서 끝난다: (가) 긴 회수(척추가 제기한 의문을 제기 뒤 20칸 이상 지나 여기서 전부 회수) · 복선의 답(척추가 먼저 흘린 2회독 암시의 사실이 여기서 처음 밝혀짐) —
  ①의 in 회수 · in 암시와 겹치고 "오래 쌓였다"는 표시다, (나) · (다) 마무리 기록 O(아래 "마무리 기록" — 쌓인 자리에 척추가 있고 끝이 여기). O는 확정만 시안에 쓰고(후보는 보이기만), 지휘관과의 관계는 표시만 한다.
- ⑧ 감정 재료(X3g — 카드 3절 3a · 4a · "결정적 순간") — 척추 인물의 결정적 순간 후보: 이 단위의 인물 변화 D(신념 · 소속 · 신체 · 기억 · 관계 — 성격 빼고)와 여기서 끝나는 확정 마무리 기록 O(관계 · 갈등 · 성장 — 연작 빼고, 척추가 쌓은 것만 — X3g-2: 척추 밖에서만 쌓인 O는 닫는 D로 본다).
  주인(D의 person · O의 about, 같은 인물 합침)이 주요 인물(아래 "주요 인물", X3g-1b)이면 상한 필수 · `from` = 주요 인물의 from, 척추 인물이면 상한 보강 · `from` = 척추 사실 3건째 자리. 지휘관과의 관계는 뺀다.
  단서: 척추 같은 줄(같은 인물 · 측면, 관계면 같은 상대의 척추 D — '여기에만'을 맞댈 곳, 가까운 셋 · 더 있으면 수 — 전부는 `query.mjs chrono <인물>`) · 척추의 둘(관계 — 둘이 about인 척추 사실 + 둘 사이 척추 관계 D) · O의 닫는 기록 · 척추가 쌓음(⑦과 겹침). 시안(draft)에는 쓰지 않는다 — 이해 등급과 따로 보고 높은 쪽이 등급.
- 기계 시안(X3f): 뼈대 줄기의 필수 쪽 연결(1회독 out · 전부 회수 · 뒤집음, 2회독 out 재언급 · in 암시)이면 필수 · 메인 연결이면 보강 · 뼈대 · 보강 줄기에 곧바로 들면 보강(추정) · 척추가 쌓은 마무리 기록(확정, 지휘관 관계 빼고 — ⑦)이면 보강(추정) ·
  뼈대 · 보강 줄기의 2회독 암시 · 뼈대 about 2건 · ④ · ⑤ · 생활상 · 줄기 인물 변화가 있으면 참고(추정) · 그 밖 독립. 참고 시안은 "메인이 말하지 않은 기록인지"를 보지 못한다 — 판정이 본다.
  2회독 없이 낸 시안(`draft1`)도 같이 보인다 — 2회독이 시안을 바꾼 단위를 가린다.

**다시 볼 묶음 (X3f)** — `node tools/views/importance.mjs`(`draft.mjs`가 같이 부른다) → `data/views/importance/`(units.csv · report.md — 척추 11은 "척추" 절에 따로, 판정 단위 421). 기준 바꿈이라 421 모두 다시 본다 —
판정에 X3f 뒤 검토 기록(세션 `X3f…` · `N3`)이 없으면 아래 묶음 하나에 든다(앞 묶음이 이긴다, 규칙은 tools/views/importance.mjs 머리말):
필수 다시(지금 필수) · 주역 원점(원점이 아직 없는 주역의 사연 — ⑤) · 메인이 딛음(메인이 이 단위의 것을 딛거나 메인 의문을 전부 회수 · 뒤집음 — 줄기 무게와 상관없이, 메인이 쌓은 것의 끝 — ⑦ 확정 마무리 기록) ·
보강 다시(지금 보강) · 참고 후보(지금 독립 — ④ · 생활상 · 줄기 인물 변화 · 줄기 암시 · 뼈대 about) · 독립 그대로(지금 독립 — 그런 입력이 없음).
report.md에는 주역마다 사연이 든 단위(원점 후보)와 메인 챕터 자리마다 등급 표가 함께 나온다. X3a–X3c의 다시 볼 까닭(2회독이 입력을 바꾼 단위)은 X3c에서 끝났다.

**감정 기준 후보 (X3g)** — 같은 도구가 `emotion.md`(후보 표, 공개 자리 순)를 쓰고 units.csv에 칸을 더한다: `emotion`(⑧ 상한) · `emotion_from` · `emotion_from_pos` · `emotion_moments` ·
`emotion_check`(`오름` = 상한이 지금 등급보다 높다 · `이른 자리` = 같은 등급인데 감정 쪽 from이 이르다) · `emotion_done`(세션 `X3g…` · `N3` 검토가 있으면 `다시 봄`). 다시 볼 묶음과 따로 센다.
감정으로 오른 판정은 reason 머리에 `감정 — `, basis는 그 순간의 D(검증기가 D가 아니면 경고한다). 새 칸은 없다 — 이해 등급은 이력(검토 기록의 before)에 남는다.

**다시 판정하는 법** — 판정 `K` 하나를 끝까지 쓴다. 바꾼 칸의 고치기 전 값은 그 검토 기록의 `before`에 남는다(`등급 독립 · 근거 J35 · 이유 …`):
```bash
node tools/records.mjs set K114 확정 --grade 보강 --basis F622 --reason "…(메인 · 줄기 ID)" --asof 2026-09-24 --session X3c --by claude --note "2회독 E102 — …"
node tools/records.mjs set K264 확정 --session X3b --by claude --note "그대로 — …"     # 바뀐 게 없어도 다른 세션이 다시 보면 검토 기록이 남는다
node tools/records.mjs set K330 확정 --grade 필수 --from ch38 --before 참고 --basis F1806 --reason "…" --session X3f-3 --by claude   # 메인 자리(X3f ⑤)
node tools/records.mjs set K124 확정 --grade 참고 --basis F651 --reason "…" --session X3f-5a --by claude                            # 참고(X3f ③)
node tools/records.mjs set Z3 확정 --origin event_staranis1 --session X3f-3 --by claude   # 주역의 원점(X3f ①) — 그 단위의 판정은 필수(--from 주역이 되는 챕터 이후), 메인 밖에 없으면 --origin 메인
node tools/records.mjs set K330 확정 --grade 필수 --from event_redash --before 참고 …           # 척추 자리(X3f-1c) — from에 척추 이벤트 · 사이드 키, 자리별 등급은 그 공개 자리로
```
- `--basis`는 이 단위의 기록 하나(사실 · 의문 · 사건 · 2회독 떡밥 E · 인물 변화 D) 또는 줄기 ID. 메인에 있는 2회독 암시의 답처럼 단위의 기록이 따로 있으면 그것을 든다(`records.mjs layers`의 `→` 뒤).
- **기준 시점**(`asof`) = 판정이 반영한 스토리의 마지막 공개일. B0b-2 판정은 모두 2026-09-24(그날까지 공개된 481단위 — X3a가 채웠다). 다시 판정하면 그때 반영한 마지막 공개일로 고친다(같으면 그대로).
  1회독 기준인지 2회독 기준인지는 검토 기록의 세션(B0b-2 → X3 · N3)이 말한다.
- **이력** = 검토 기록. 시안 표의 `history` 칸이 `B0b-2 독립 → X3c 보강 · N3 그대로`처럼 편다(tools/views/importance.mjs `gradeHistory`).
- **층은 읽은 층으로 묶는다** — 2회독이 끝났으므로 층은 그 단위를 2회독에서 읽은 층(docs/history/reading.md P · M의 `#### N층` — `parseReadLayers`)이다. 등급을 바꿔 규칙 층이 달라지면
  검증기가 경고한다 → `set K… 확정 --layer <읽은 층> --note "2회독은 N층에서 읽음"`. 층은 2회독의 깊이(생활상은 1층에서만)를 말하므로 바꾸지 않는다.
  `--layer`와 함께 준 `--note`는 검토 기록과 판정의 `note`(층을 뒤집은 까닭 — 검증기가 본다)에 함께 남는다(X3b). 등급과 층을 한 번에 바꿀 때는 note에 층 까닭도 적는다.

**판단 원칙 · 재료 → [importance.md](importance.md) (판정 카드)** — 중간점검(2026-10-09, 사용자 요청)으로 등급의 정의 · 판정 순서 · 잣대를 한 장에 모았다. 판정 세션은 카드만 읽고 판정한다.
X3b(2026-10-08) · X3c(2026-10-09) 판단 재료와 X3f(2026-10-09) 판단 원칙은 카드의 순서(3절)와 예시(8절)로 옮겼다 — 기록 note의 "X3b 원칙" · "X3c"는 그때의 잣대를 가리킨다.
이 절에 남는 것은 도구 · 형식이다: 판정 입력 · 다시 볼 묶음 · 다시 판정하는 법(위) · 기준 시점 · 이력 · 층.

## 척추 — `annotations/spine.json` (X3f-1b · 1c)

척추 = 메인 챕터 + **게임이 큰 이야기로 내놓은 이벤트 · 사이드 가운데 메인의 뼈대를 메인과 함께 나르는 것**(사용자 결정 2026-10-09 — 주년 · 신년 같은 메인급 이벤트는 메인급). 채점하지 않는 기준이다 — 뜻은 [importance.md](importance.md) 1절, 선정 기준 · 계산은 tools/views/spine.mjs 머리말과 [data/views/importance/spine.md](../data/views/importance/spine.md), 처음 고른 기록은 [spine-candidates.md](../data/views/importance/spine-candidates.md).
고르는 것은 Claude, 사용자는 기준(`criteria`)에 피드백을 준다 — 기준이 바뀌면 Claude가 항목을 다시 판정한다(`set B… 확정|기각 --note "…"`).

```json
{ "session": "X3f-1c", "by": "claude", "date": "2026-10-09",
  "criteria": { "skeleton": 3, "main": 3, "payoff_gap": 20, "payoffs": 2, "answers": 5 },
  "spine": [
    { "id": "B2", "unit": "event_redash", "gate": "1주년", "notice": "2023-10-30 「11월 2일 업데이트 공지」 — \"1ST ANNIVERSARY PARTY, RED ASH 이벤트\"",
      "reason": "문 1주년 · ⓐ 8 · ⓒ 0 · 5 · ⓑ 9 — …", "confidence": "확실", "status": "확정", "reviews": [ … ] },
    { "id": "B5", "unit": "event_unbreakablesphere1", "gate": "2.5주년", "reason": "… ⓑ 미달", "status": "기각", … }
  ] }
```

| 칸 | 필수 | 뜻 |
|---|---|---|
| `id` | ✓ | `B<n>` — 한 번 붙이면 바꾸지 않는다 |
| `unit` | ✓ | 읽기 단위 키 — 이벤트 · 사이드만(메인은 늘 척추, 이벤트 유실물 · 연작의 다른 편은 판정 단위). 한 단위에 항목 하나 |
| `gate` | ✓ | 문 — 공지가 소개한 말(`1주년` · `하프(0.5주년)` · `연말 · 신년` · `신년`)이나 `사이드` |
| `notice` | | 공지 근거(게시일 · 제목 · 말, `data/raw/notices/`) — 사이드는 없다 |
| `reason` · `confidence` · `status` · `reviews` · `by` · `note` | | 후보 공통 칸. reason은 문 · ⓐ · ⓒ · ⓑ 수와 까닭. **확정 = 척추, 기각 = 문 안이지만 기준 미달**(판정 단위로 남는다) |
| 파일 `criteria` | | 문턱 — ⓐ `skeleton` 뼈대 기록 · ⓑ `main` 메인 연결 · ⓒ `payoff_gap`칸 뒤 전부 회수 `payoffs`건, 또는 복선의 답 `answers`건. 사용자가 조율한다 |

- 문 안 단위는 모두 적는다(지금 17 — 척추 11 · 미달 6). 문은 기계로 읽지 않는다 — 신작마다 Claude가 공지를 보고 항목을 더하고 `node tools/views/spine.mjs`로 계산해 확정 · 기각한다(N3).
- 척추 단위에 미치는 것: 판정 입력 ①의 "척추 연결"(메인 챕터와 같은 무게) · 시안 표에서 빠짐(판정 K는 "척추" 표시) · 층 1 · `from` · `arcs` · `origin`에 척추 키 · 주역 초안의 축(아래) · `find --spine`.
- 계산(`spine.md`)이 판정과 어긋나면 보고서 "어긋남"에 뜬다 — 기준을 바꿨으면 항목도 같이 고친다. 테스트가 X3f-1b가 손으로 센 수와 맞춘다(tests/spine.test.mjs).

## 주역 명단 — `annotations/leads.json` (X3f ① · X3f-1c)

메인 주역은 **자리별 명단 하나**다(인물마다 등급을 매기지 않는다 — 주역인가 아닌가와 언제부터인가만). 중요도 판정의 주역 조항(카드 3절 2)이 이 명단을 딛는다.
**주역 = 뼈대 줄기의 주인 + 카운터스 · 지휘관**(사용자, 2026-10-09 — 첫 기준의 손 판단은 잣대가 제각각이었고 동일인을 합치지 않았다). 주인은 줄기마다 그 줄기가 정체를 묻는 1–2명이고 Claude가 근거와 함께 정한다(`threads[].owners`).
손으로 넣고 빼지 않는다 — 주인을 바꾸려면 owners를 고친다. 같은 인물(people.json 확정 `same_as`)은 합쳐 대표 ID로 적는다. from · 범위는 기계 그대로. 단계로 나누지 않는다(주역이면 원점 하나가 필수 — 표에서만 메인 전체 / 구간을 갈라 보인다).
명단은 해석이라 Claude가 확정한다(사용자는 기준에 피드백 — CLAUDE.md "일하는 법"). 예시: [tests/fixtures/read1/_leads.json](../tests/fixtures/read1/_leads.json).

```json
{ "session": "X3f-1c", "by": "claude", "date": "2026-10-09",
  "threads": [ { "thread": "J12", "owners": ["person:그레이브", "person:신데렐라"], "reason": "언노운 = 그레이브의 정체(Q142 · Q170 · Q204), 신데렐라의 과거와 행방(Q207 · Q216) …", "confidence": "확실" },
               { "thread": "J9", "owners": [], "reason": "사건 · 개념의 줄기, 묻는 사람이 없다", "confidence": "확실" } ],
  "counters": ["person:라피", "person:아니스", "person:네온", "person:지휘관"],
  "leads": [
    { "id": "Z30", "person": "person:레비아탄", "from": "ch32", "records": ["J10", "D556", "D631", "D632"], "reason": "ch32부터(첫 고른 구간의 처음 중심) 걸린 자리 15/25 … — J10의 주인 · 같은 인물 합침: 레비",
      "confidence": "추정", "status": "확정", "reviews": [ … ] },
    { "id": "Z47", "person": "person:릴리스", "from": "fl:ark_guardian", "arcs": ["fl:ark_guardian-ch47"], "origin": "…", … }
  ] }
```

| 칸 | 필수 | 뜻 |
|---|---|---|
| 파일 `threads[]` | ✓ | 뼈대 줄기마다 `thread`(J) · `owners`(인물 ID 0–2명) · `reason`(줄기 제목 · 의문이 묻는 사람) · `confidence`. 주인이 없는 줄기도 `owners: []`로 적는다(검증기가 빠진 줄기를 알린다) |

**확정 기준**(Claude, X3f-1d — 사용자는 이 기준에 피드백). 사슬마다 기록 문장을 읽고(원문은 다시 읽지 않는다) "쌓인 것이 이 자리에서 끝나는가"를 본다:
- **확정** — 닫는 기록이 끝을 보인다: 갈등은 결판(승패 · 화해 · 결별 · 죽음 · 한쪽이 내려놓음 — 적대 · 경쟁의 관계 사슬이면 `--type 갈등`) · 관계는 자리 잡음(털어놓음 · 오해가 풀림 · 신뢰를 확인 · 이별 · 사별 — 뒤에 다시 크게 뒤집히지 않는다) ·
  성장은 이룸(쌓인 결핍 · 상처 · 목표가 풀리거나 새 신념이 서서 그대로 간다) · 연작은 마지막 편이 연작의 핵심 물음 · 대립을 닫는다.

- **끝이 마지막 변화가 아니면** 고쳐서 확정 — 가운데 변화에서 끝나고 그 뒤가 새 국면이면 `--end <단위> --closing "<기록>" --built "<그 앞 기록들>"`. 연작의 마지막 편이 뒷이야기뿐이면 결판 편으로 `--end`.

### 합류 기록 — `merges` (X3f-1g)

마무리 기록은 끝 하나에 하나라 **한 결판에서 여러 줄이 함께 끝나면** 화면 3 · 5에서 한 이야기의 끝이 점 여럿으로 흩어지고, 셋 이상의 관계는 쌍 사슬로 쪼개져 같은 닫는 기록을 두 번 쓴다(D1239 · D1744).
합류 기록 H는 그 마무리들을 결판 하나로 묶는다(사용자 물음 "사슬이 섞이거나 분화되는 것도 다뤘나?", 2026-10-09 — 형식은 Claude가 정했다). 예시: [tests/fixtures/read1/_closures.json](../tests/fixtures/read1/_closures.json) H1.

```json
{ "id": "H9", "title": "STAR ANIS — 아니스의 마지막 무대", "end": "event_staranis1", "members": ["O67", "O68", "O72", "O73", "O75", "O79"],
  "text": "프리티의 죽음 뒤 이어진 T.T.STAR의 이야기가 아니스의 마지막 무대에서 결판나며 …", "reason": "…", "confidence": "확실", "status": "확정", "reviews": [ … ] }
```

| 칸 | 필수 | 뜻 |
|---|---|---|
| `id` | ✓ | `H<n>` |
| `title` | ✓ | 결판 이름 — 화면에 뜨는 말(GODDESS FALL 결전 · 토브의 호감도 마지막 편) |
| `end` | ✓ | 함께 끝난 단위 키 — 멤버의 `end`가 모두 이것이어야 한다(오류) |
| `members` | ✓ | 함께 끝난 마무리 기록 O 둘 이상(기각된 O는 오류). 한 O는 한 합류에만(경고) |
| `text` | ✓ | 무엇이 함께 끝났나 한 문장 |
| `reason` · `confidence` · `status` · `reviews` · `by` · `note` | | 후보 공통 칸 |

- **묶는 기준**(Claude, X3f-1g — 사용자는 이 기준에 피드백): 같은 단위에서 끝나는 확정 O 둘 이상이 **한 이야기의 한 결판**일 때 — 한 결전 · 무대(GODDESS FALL · ch48 · STAR ANIS), 연작의 결판 편과 그 안 인물의 끝(CLAY, MORE! · TERMINUS TICKET),
  한 사람의 귀순 · 고백 장면(ch42 레비아탄 · ch44 스노우 화이트), **한 니케의 호감도 마지막 편**이 그 니케의 관계와 성장을 함께 닫을 때(사슬 초안이 측면 — 성격 · 신념 · 관계 — 으로 나눈 한 이룸).
- **묶지 않는다**: 같은 단위라도 줄이 다른 이야기 — 메인 챕터의 다른 줄(ch35 그레이브 · 라플라스, ch45 리버린 · E.H., ch46 나유타 · 도로시, ch47 도로시 · 요한 · 에닉), 한 이벤트의 다른 두 이야기(NEW YEAR, NEW SWORD 노이즈 · 홍련),
  같은 챕터의 다른 결판(ch42 모리는 레비아탄과 따로 묶는다). 끝이 다른 단위인 같은 인물의 측면(마리안 O12 · O106)은 두 단계라 묶지 않는다 — 인물로 이어 보는 것은 화면 5의 계산이다.
- **셋 이상의 관계를 기록 하나가 닫으면**(쌍 사슬이 하나뿐 — 아인 · 츠바이 · 라이 O148, 마스트 · 헬름 · 앵커 O159, E.H. · 바이퍼 · 자칼 O197) 합류가 아니라 그 O의 `about`을 셋으로 넓힌다(`set O… 확정 --about "…"`).
- 쓰기: 손으로 `merges`에 후보로 더하고 `set H… 확정 --session … --by claude`. 고치기는 `--members "O1 O2"` · `--title` · `--end` · `--text`. 보기: `records.mjs closures H9`(멤버 문장) · `closures <단위>`(그 단위의 합류) · `data/views/closures/merges.csv` · report.md "합류".
- 판정 입력 ⑦은 낱낱의 O를 그대로 센다 — 묶어도 판정 묶음 수는 바뀌지 않는다(X3f-1g에서 draft.mjs로 확인).
- X3f-1g: 합류 27(묶인 마무리 87 — 결전 · 무대 · 연작 · 한 장면 17, 호감도 마지막 편 10).

**쓰는 곳**: 판정 입력 ⑦(위 "중요도 판정" — 확정 · 척추가 쌓음 · 지휘관 관계 아님이면 시안 보강 · 묶음 "메인이 딛음", 판정은 카드 3절 4) · 화면 3 떡밥 흐름(줄기 · 갈등의 결말) · 화면 5 인물 곡선(관계 · 성장의 끝) — docs/views.md. 합류 H는 화면 3 · 5에서 결판 하나로 모은다.
신작(N3)마다 `closures --add`로 새 사슬을 후보로 더해 본다 — 끝난 사슬이 다시 움직이면(새 변화) 기록의 끝을 고치거나 새 기록을 더한다.

## 2회독 기록 — `annotations/read2/<키>.json` (B1a)

2회독(대사 층)은 1회독 사실 · 의문 · 떡밥 줄기를 다 들고(결말을 알고) 원문을 한 번 더 읽으며, 1회독이 남기지 않은 것 — 이름 없이 가리킨 대목,

docs/history/reading.md P · M 머리말, 얼마나 잘게 · 어디까지(예: 평범한 대명사)는 아래 "2회독 기준"(P1). 모두 해석이라 후보 → Claude가 단위마다

### 2회독 기준 (P1, 2026-10-05 — 이후 세션은 이것을 따른다)

P1(ch00–03 · 서브퀘스트 6 · 유실물 4, 원문 4.6만 자)을 읽고 Claude가 정했다. 사용자는 이 기준에 피드백을 준다. 실측은 docs/history/reading.md P1 인계.

**읽는 법 — 한 번 읽고 두 번 훑는다.** 단위마다 원문을 한 번 읽은 뒤 ① 네 측면(암시 언급 · 떡밥 · 인물 변화 · 생활상)을 한 번에 뽑아 적고,
② 같은 출력에서 측면 하나씩 다시 훑어 ①이 놓친 것을 더한다(원문을 다시 열지 않는다). P1에서 ②가 18%를 더했고(72건 중 13 — 떡밥 5/20 · 인물 변화 6/31 · 생활상 2/20),
값진 것이 많았다(라피의 옛 몸 E10 · '이레귤러' E8). 그래서 두 단계를 지킨다. `pass` 칸은 P1 비교용이라 M부터는 적지 않는다.

**얼마나 잘게** — 한 기록 = 한 씬 · 한 가지 뜻. 같은 씬에서 같은 것을 가리키는 줄은 한 기록에 근거 줄을 여럿 둔다.
- **떡밥(E)**
  - 암시는 **뒤에 드러나는 특정 사실 · 의문 · 사건을 가리킬 때만** 적는다. 어디에나 붙는 말('예외는 있는 법')은 적지 않는다(P1 E9 기각).
  - 1회독 의문의 제기 → 회수가 이미 같은 씬에서 같은 답으로 이어지면 적지 않는다(엣지가 겹친다). 제기 씬 **밖**의 앞 씬이 흘린 것은 적는다.
  - 같은 단위 안의 앞 씬 → 뒤 씬 암시도 적는다(E3 · E4 — 화면 3의 단위 안 흐름).
  - 인물이 남에게 한 말이 뒤에 자기에게 돌아오는 반어 · 모티프 · 주제의 메아리는 **추정**으로 적는다(E2 · E18).
  - 줄기만 가리키는 암시(`J<n>`만 — 씬 엣지 없음)는 가리킬 사실 · 의문이 없고 그 줄기의 첫 그림일 때만(E13 · E19).
  - 재언급은 앞 단위의 사실 · 사건을 다시 꺼낼 때. 되풀이되는 소품 · 모티프(붕대)는 1회독 사실이 없으면 **바로잡기로 사실을 세운 뒤** 가리킨다(F2880 → E16).
- **인물 변화(D)**
  - 기준은 이름 있고 되풀이해 나오는 인물만, 그 씬이 실제로 그린 측면만 적는다. 한 번 나오고 마는 단역은 적지 않는다.
    관계 기준은 상대(`with`)마다 하나 — 지휘관과의 관계를 먼저, 다른 인물과의 관계가 줄거리의 축이면 그것도(유니 → 미하라 D29).
  - 변화는 전 → 후가 원문의 말 · 행동으로 분명할 때만. 말투가 상대에 따라 다른 것은 변화가 아니다. 죽음 · 소속 이동 · 몸의 큰 변화는
    1회독 사실이 있어도 `points`로 이어 타임라인에 올린다(마리안의 처분 D8 · 카운터스 D11).
  - 서브퀘스트 · 유실물의 단역은 지휘관과의 관계 변화만 적는다(콜렉터 D28). 몸 · 소속 같은 다른 측면은 1회독 사실로 둔다.
- **생활상(U)** — 제도 · 계층 · 생계 · 기술 · 풍습 · 사람들의 인식이 **어떻게 살아지는지** 그려진 곳. 단위 · 주제마다 1–2건, 같은 모습이 되풀이되면 처음 씬만(새 면이 더해질 때만 또).
  1회독 사실과 겹치면 `points`로 잇고 문장은 사는 모습 쪽으로 쓴다. 군 규칙 · 작전 절차 자체는 1회독 사실로 충분하다 — 그것이 사람 사는 모습으로 그려질 때만(일회용 지휘관 U18).
  방주 이전 · 랩쳐 전쟁 때의 삶(유실물)은 주제 `구시대`.
- **암시 언급(I)** — 적는 것: (a) 그 씬에 이름표 · 이름 · 별칭으로 안 잡히는 대상을 이름 없이 가리킬 때(`query.mjs targets <단위>`에 그 씬이 없으면 — 세르반의 '까마득히 높은 상사인 아버지' = 버닝엄 I1),
  (b) `???` · 미상 이름표의 정체(`speaker: true`). 적지 않는 것: 그 씬에 이미 나온(말하거나 이름이 불린) 대상을 대명사 · 호칭으로 가리키는 줄('댁' · '이분' · 2인칭 · 대화 상대) —
  씬 단위 집계(화면 5)에 더할 것이 없다. 사전에 없는 단역(04-F의 전 지휘관 · 선발대)은 두 단위 이상에서 줄거리에 걸릴 때만 사전에 더하고 적는다.
  - `???` 정체(M01이 처음 적용 — ch04 · ch06 · 서브퀘스트 2곳 모두 정함, 못 정한 줄은 ch05 `소녀` 하나라 기준 그대로): 원문으로 정할 수 있으면 그 인물로(확실 · 추정). 무리 · 이름 없는 단역(병사 · 시민)이라 정할 수 없으면 기록하지 않고
    2회독 파일 `note`에 `정체 볼 줄 — 정할 수 없음: 씬#줄 (이유)`로 남긴다(진행률의 남은 줄과 맞춰 볼 수 있게).

**확실 / 추정** — 확실: 원문 줄이 직접 보여 주거나, 뒤 원문이 이 장면을 분명히 되짚는다(E10 — 지휘관이 '예전 그레이브 디거 전에서 소실된 바디'라 한다).
추정: 반어 · 모티프 · 주제의 메아리, 같은 일이라는 확인이 원문에 없는 것, 줄기만 가리킬 때. 추정도 검토해 확정할 수 있다(확신도는 기록의 성격, 상태는 검토 결과).

**1회독 바로잡기** — 줄거리 사실이 빠졌으면 세운다(되풀이되는 소품 · 모티프도 뒤에서 재언급할 대상이면). 그 단위의 1회독 추정은 다시 볼 수 있으면 다시 본다(F67 → 확실).
인계 파일의 근거는 첫 씬만 보이니 근거 줄을 고치기 전에 `review F…`로 전체 근거를 본다.

**시점 단서 보강 (2 · 3층, C1 2026-10-08 — 사용자가 작중 시간순 나열을 원한다, docs/views.md 화면 6)** — 단위에 시점 기록(`S`)이 없거나 회상 구간이 빠졌는데
원문이 실마리를 주면 바로잡기로 시점을 더한다(1회독 파일 `times` + `session`). 실마리: 이름이 나온 사건 · 챕터와의 앞뒤('갓데스 폴 70년 뒤', '아크 가디언 뒤'),
합류 · 사망 · 소속 이동 · 몸의 변화를 이미 겪은 상태로 나오는 인물, 작중 날짜 · 나이. 범위만 알면 범위로 — `text`에 `CH.20 뒤 · CH.31 전`처럼, `ref`는 가장 가까운 기준 하나.
인물 상태로 좁힌 것은 추정. 출시 시기 · 계절 이벤트라는 것만으로는 적지 않는다(작중 시점이 아니다). 실마리가 없으면 적지 않는다 — 시점 불명은 X1이 센다.
새 시점 기록에는 `at`(관계 · 기준)을 같이 쓴다 — 아래 "작중 연대기"(X1b).
1층 단위의 빈 곳은 X1이 기존 기록으로 좁힌다(1층은 다시 읽지 않는다).

**되짚어 읽기 · 넘기기** — 결말은 인계 파일(줄기 결말 · 의문의 답)과 `records.mjs find` · `query.mjs search`로 확인하고, 뒤 단위를 읽어야 정해지는 것은
`revisit`(`where` = 그 단위)으로 넘긴다(V1 — Q246 '그 사람' → ch04). P1 되짚어 읽기 0자(검색 1회).

**이유(reason)는 짧게** — 근거 줄 인용 + 무엇과 잇는지, 두 문장 · 150자 안쪽. 컨텍스트를 아낀다(P1은 길었다).

**파일 칸** — `unit` · `parts` · `session`(2회독 세션 `P1` · `M03`, 읽기 순서와 다르면 경고) · `by` · `date`는 1회독과 같다. `summary` · `scenes`는 없다(1회독 요약을 쓴다).
`mentions` · `echoes` · `changes` · `life` · `revisit` · `revisitDone` · `slips` · `note`. 1회독 칸(`facts` · `questions` · `events` · `times` · `targets`)을 쓰면 오류다 — 바로잡기는 1회독 파일에.

**공통** — 후보 공통 칸(`id` · `evidence` · `reason` · `confidence` · `status` · `by` · `note` · `reviews`) 그대로. 더해:
- **한 기록 = 한 씬** — `evidence`의 씬은 하나(줄 범위는 여럿 된다). 두 씬에 걸치면 씬마다 따로 적는다. 근거 첫 줄이 그 기록의 자리이고 엣지 끝점이다.
- 줄 하나는 숫자(`12`), 범위만 문자열(`"20-25"`) — 1회독 형식 메모. 뼈대의 `_comment`에 예가 있다.
- `pass`(선택, P1 비교용): `1` = 네 측면을 한 번에 뽑을 때 적은 것, `2` = 측면 하나씩 다시 훑어 더한 것. P1이 ②가 더한 수를 측면별로 센다.

|---|---|
| 암시 언급 `I` | `target`(대상 ID, 필수) · `speaker`(선택 `true` — 그 줄을 **말한** 사람이 이 대상: `???` · 미상 이름표의 정체. 인물만, 대사 줄만) |
| 떡밥 `E` | `act`: `암시` · `재언급`(필수) · `points`(가리키는 기록 ID 배열, 필수 — 사실 `F12` · 의문 `Q3` · 사건 `Q3-2` · `F12-2` · 줄기 `J1`) · `text`(무엇을 흘렸나 · 다시 꺼냈나 한 문장, 필수) · `about`(대상, 선택) |
| 인물 변화 `D` | `person`(인물 ID, 필수) · `aspect`(필수) · `act`: `기준` · `변화`(필수). 기준: `text`(처음 모습 한 문장, 필수). 변화: `before` · `after`(짧은 구절, 필수) · `text`(선택) · `trigger`(계기 씬 — evidence 모양, 씬 하나, 다른 단위여도 된다) · `with`(관계 상대 대상 ID — 관계면 적는다) · `time`(작중 시점 `S<n>`, 선택) · `points`(선택) |

### 암시 언급 (`I`, T4-7)
- 대상은 사전 ID다 — 인물만이 아니라 장소 · 조직 · 개념 · 사건 · 물건도 된다(예시 `I1`: 이름 없이 갓데스 폴의 니케들을 가리킴). 사전에 없으면 1회독처럼 사전에 먼저 더한다.
- `speaker: true` — `???` 같은 미상 이름표 줄의 정체. 범위 안 미상 이름표 줄은 963줄(`???` 829 · 그 밖 8종 134 — `남자의 목소리` 89 · `익명` 14 · `곰…?` 13 · `수수께끼의 미소녀` 10 …)이고
  1회독 정체 연결(people.json `L<n>` 30)이 잇는 줄은 **0**이라 모두 2회독 몫이다(B1a 실측, `lines.speaker_class = '미상'`). 이름표가 이미 그 인물로 풀리는 줄이면 경고한다 — 자동(`speaks`)이 잡는다.
- 같은 대상 · 같은 줄을 두 번 적으면 경고. 어디까지 넣을지(대화 속 평범한 대명사 등)는 "2회독 기준"(P1)을 따른다.

### 떡밥 — 암시 · 재언급 (`E`, T4-2)
- **암시** = 가리킨 것이 드러나기(의문이면 회수되기) **전에** 행동 · 묘사 · 말로 흘린 것. **재언급** = 이미 드러난(의문이면 제기된) 것을 **뒤에서** 다시 꺼낸 것.
  드러내 놓고 새로 밝히면 암시가 아니라 1회독 드러냄 · 회수다 → 바로잡기. 이미 아는 것을 독자에게 다시 **밝히면** 1회독 드러냄(`F<n>-k`), **가리키기만** 하면 재언급.
- `points`는 필수 — 2회독 기록이 바로 엣지가 되려면 무엇을 가리키는지 기계가 알아야 한다(views.md "B1에 넘기는 것"). 줄기만 알면 `J<n>`, 사실 · 의문을 알면 그것을(둘 다 적어도 된다).
  가리킬 사실 · 의문이 1회독에 없으면 바로잡기로 먼저 세운다.
- 앞뒤는 **출시순 한 줄**(1회독 순서)로 잰다 — 2회독을 층별로 읽어도 같다. 암시가 가리킨 것의 드러남보다 뒤거나 재언급이 앞이면 검증기가 경고한다(act를 다시 본다).
- **엣지**(tools/records/read2.mjs, 끝점 = 근거의 첫 씬, 방향 = 읽는 순서 — docs/schema.md "엣지 타입"):

  | act → 가리킨 것 | 엣지 | from → to |
  |---|---|---|
  | 암시 → 사실 `F<n>` · 사건 `F/Q<n>-k` | `setup_payoff` | 암시 씬 → 그 기록의 첫 씬 |
  | 암시 → 의문 `Q<n>` | `setup_payoff` | 암시 씬 → 회수(`Q<n>-k`)마다 그 첫 씬. 회수가 없으면 엣지 없음(열린 떡밥) |
  | 재언급 → 사실 · 의문 · 사건 | `callback` | 그 기록의 첫 씬 → 재언급 씬 |
  | 줄기 `J<n>` | — | 씬 엣지 없음. 화면 3(줄기 흐름)에만 |

- 여러 씬에 근거를 둔 1회독 사실(1,227건)은 다시 쓰지 않는다 — 엣지 끝점은 근거의 첫 씬이고, 2회독의 씬 단위 기록이 그 사실을 가리킨다(R99 형식 메모).

### 인물 변화 (`D`, T4-8)
- 측면(`aspect`): `성격`(성격 · 태도) · `관계`(지휘관 · 다른 인물) · `소속`(소속 · 지위) · `신체`(신체 · 상태) · `신념`(목표 · 신념) · `기억`(기억 · 정체).
- **기준** — 인물 · 측면마다 하나(관계는 상대 `with`마다 하나 — 유니 → 미하라와 유니 → 지휘관은 따로, P1), 그 측면의 처음 모습. 근거는 그 모습이 처음 그려진 씬. 층별로 읽으므로 더 앞선(출시순) 모습을 뒤에 만날 수 있다 — 그러면 앞선 쪽을 남기고 다른 하나는 기각한다(둘이면 경고).
- **변화** — 전 → 후를 짧은 구절로. `evidence` = 바뀐 것이 **드러난** 씬(기록의 자리), `trigger` = 바뀐 **계기** 씬(앞 단위여도 된다). 기준 없이 변화만 있어도 된다(기준은 다른 층에서 나올 수 있다).
- 출시순(읽는 순서)으로 쌓고 작중 시점 ID(`time` — 1회독 `S<n>`)를 단다. 작중 시점 순 정렬은 X1이 계산한다(T4-8의 "작중 시점 순"을 이렇게 읽는다).
  X1d ✅: `time`이 있으면 그 시점 기록의 자리(단위의 '지금' · 조각), 없으면 기록이 있는 단위(드러난 단위)의 작중 자리에 놓는다 — 계기(`trigger`)가 앞 단위여도 드러난 쪽.
  인물마다 작중 순서 · 뒤바뀜(먼저 공개된 변화보다 작중 앞): `data/views/timeline/chrono-changes.csv` · `node tools/query.mjs chrono person:라피`. 새 칸은 없다.
- 이명 · 이름표가 달라도 사전의 같은 인물 ID로 적는다(라피 / 라피 : 레드 후드 → `person:라피`).
- 읽을 곳을 좁히는 자동 신호(B2): `node tools/query.mjs signals <인물> --flags` — 단위별 이름표 · 존댓말 비율 · 지휘관 호칭이 앞과 달라진 곳(◆).
  해석이 아니다 — ◆ 단위를 읽을 때 변화로 적을지 정한다(말투가 상대에 따라 바뀐 것뿐이면 적지 않는다). 표 전체는 `data/views/mentions/changes.csv`.

### 세계 생활상 (`U`, T4-9)
- 주제(`topic`): `방주 사회` · `지상`(지금의 지상) · `구시대`(방주 이전 · 랩쳐 전쟁 때 사람들의 삶 — 유실물에 많다, P1이 더함) · `전초기지` · `기업 · 조직` · `일상 · 문화` · `경제` · `기술`. 읽으면서 늘린다 — tools/records/model.mjs `LIFE_TOPICS`와 여기에 더한다(목록에 없으면 경고).
- 드러나는 순서보다 "무엇이 어떻게 그려지나"가 핵심이다. 처음 그려진 씬을 근거로, 출시순으로 쌓는다. 속사정이 뒤에 밝혀지면 `points`로 그 사실 · 줄기를 잇는다.
- 1층에서만 한다(docs/history/reading.md P · M 머리말).

### 1회독 바로잡기

2회독이 1회독 기록을 고치는 길이다. "읽기 세션은 자기 단위 파일만 고친다"의 예외 — **지금 읽는 단위의 1회독 파일**에 더하고, 이미 있는 기록은 리뷰 도구로만 고친다.

| 무엇 | 어떻게 |
|---|---|
| 놓친 회수 · 드러냄 · 뒤집음 | 그 일이 일어난 단위(= 지금 읽는 단위)의 1회독 파일 `events`에 1회독 형식 그대로(`Q12-3` …) + 항목에 `"session": "M03"` |
| 놓친 사실 · 의문 · 시점 | 1회독 파일 `facts` · `questions` · `times`에 + `"session"`. 새 의문은 떡밥 줄기(threads.json)의 `questions`에 넣는다(빠지면 경고) |
| 추정 다시 보기(1회독 추정 82건) | 맞으면 `set F12 확정 --confidence 확실 --session M03 --note "…"`, 틀리면 `set F12 기각 --session M03 --note "…"`(가리키는 기록도 정리) |
| 문장 · 근거 줄이 틀림 | `set F12 확정 --text "…"` · `--evidence "씬#12,20-25"` — 후보 하나, 고치기 전 값은 검토 기록 `before`에 남는다 |
| 아직 2회독하지 않은 단위의 것 | 그 단위를 읽지 않았으니 적지 않는다 — 2회독 파일 `revisit`(`V<n>`, `where`에 그 단위 키)으로 넘긴다. 2회독 인계(B1b)가 그 단위 차례에 보인다 |

- 항목의 `session`은 바로잡기 표시다 — 그 항목은 1회독 기록 그대로 쓰이고(시안 · 줄기 · 층 계산이 바로 반영), `review M03` · 진행률이 2회독 세션 것으로 센다.
  `session`이 2회독 세션 모양이 아니면 오류, 그 단위의 2회독 항목과 다르면 경고.
- 바로잡기로 1회독 기록을 고치면 1회독 시안(`node tools/views/draft.mjs`)과 1회독 인계 파일(`records.mjs handoff`)이 바뀐다 — 같이 다시 만든다.
- 바로잡기로 무거워진 단위는 층 판정을 다시 볼 수 있다(`set K… --grade`, X3) — 층이 바뀌면 남은 M 목록을 다시 뽑는다("층 판정").

### 검증기 — 2회독에서 더 보는 것
오류: 2회독 파일의 1회독 칸 · 2회독이 아닌 session, ID 모양(`I` · `E` · `D` · `U` · `Y`), 한 기록에 씬 둘 이상, 없는 대상(`target` · `person` · `with` · `about`) · 인물이 아닌 `person` · `speaker`,
`act` · `aspect` 값, 떡밥의 `points` 없음 · 없는 기록 · 기각된 기록, 변화의 `before` · `after` 없음, 없는 `time`.
경고: 순서와 어긋난 암시 · 재언급, 이름표로 이미 풀리는 `speaker` 줄 · 서술 줄, 같은 대상 · 같은 줄 두 번, 인물 · 측면(관계는 상대)의 기준 둘, 관계 변화에 `with` 없음, 목록에 없는 생활상 주제,
2회독 순서(P · M)와 다른 세션, 1회독 기록이 없는 단위.

`node tools/records.mjs handoff`가 기록에서 만든다. 손으로 고치지 않는다. 같은 기록이면 같은 파일이 나온다.

- **먼저 읽을 것**은 HANDOFF.md · questions.md · recent.md · focus.md다(H1, 2026-09-29). 전체 사실 목록은 단위 수에 비례해 늘어
  1회독 끝에는 25만 자를 넘으므로 늘 읽지 않는다. 합계가 HANDOFF.md에 나오고, 6만 자(docs/operations.md "컨텍스트 예산")를 넘으면 경고한다.
- **focus.md 고르는 법**(`tools/records/focus.mjs`, 기계적 · 결정적):
  1. 다음 항목(읽기 순서에서 아직 기록이 없는 첫 단위의 세션 — 그 세션의 남은 단위)의 원문 줄마다 대상을 뽑는다 —
     이름표 → 대상(DB `speakers.targets`) ∪ 대사 속 사전 이름(DB `target_names`, 오탐 주의 이름 · 한 글자 이름은 뺀다, 검색 규칙은 사전 검색기와 같다). 대상마다 걸린 줄 수를 센다.
  2. 직전 세션이 아닌 앞 사실마다 점수 = Σ(`about` 대상 중 원문에 나온 것) log2(1 + 원문 줄 수) ÷ 그 대상을 다룬 사실 수.
     지휘관 · 니케처럼 사실이 많은 대상은 한 사실에 주는 몫이 작고, 이번 원문의 주인공처럼 드문 대상은 크다.
  3. 점수 순으로 예산이 찰 때까지 담는다. 예산 = 6만 자 − HANDOFF.md 몫(3천) − questions.md − recent.md, 8천~2만 자 사이. "필요할 때 여는 것" 전체 목록은 세션마다 늘어 HANDOFF.md가 아니라 `handoff/index.md`에 둔다.
     파일에는 가장 크게 이바지한 대상 절(점수 높은 순) 아래에 읽은 순서로 적고, 머리말에 원문에 많이 나오는 대상 상위 20과 못 담은 사실 수를 적는다.
  - 그래서 사실의 `about`이 인계에 쓰인다 — 그 사실이 다루는 대상을 빠짐없이 적는다. 원문 속 이름표 · 이름으로만 뽑으므로
    이름 없이 가리킨 대상(`???` · 대명사)은 못 잡는다 — 읽다가 앞 사실이 더 필요하면 `records.mjs find`로 찾는다(되짚어 읽기 예산 밖, 인계 파일 읽기다).
- 파일 하나는 2만 자 안쪽이다 — 목록 · 세션 요약이 넘으면 절(세션 · 단위) 경계에서 `facts-1.md` · `R01-1.md` …로 나뉜다.
  세션 요약은 `grep -n "^## " <파일>`로 단위 절을 찾아 그 부분만 읽는다.
- 2회독은 따로 만든다 — 아래 "2회독 인계 파일"(B1b, `tools/records/handoff2.mjs`). 1회독 인계 파일은 1회독이 끝난 뒤에도 남겨 2회독이 "필요할 때" 연다(사실 목록 · 의문 · 세션 요약).
- 기각된 것은 뺀다. 원문을 다시 볼 때는 씬 ID로 `node tools/read.mjs <씬> --num` — 챕터째 다시 읽지 않는다(되짚어 읽기 예산).

## 2회독 인계 파일 — 2회독 세션이 원문 대신 먼저 읽는 것 (B1b)

`node tools/records.mjs handoff`가 1회독 인계와 함께 만든다(`tools/records/handoff2.mjs`). 손으로 고치지 않는다. 같은 기록이면 같은 파일이 나오고,
`check` · `node --test`가 오래됐으면 알린다. 2회독은 결말을 알고 읽어야 복선이 보이는데 1회독 사실 전체(약 40만 자)는 못 읽으므로, **다음 세션 단위마다 기계적으로** 고른다.

### 단위 절 (next.md)

`## <키> · 제목 — 종류 · N층 · 등급(판정 K · 근거 한 건, 추정이면 X3가 다시 본다) · 1회독 세션` 아래에:
1. **볼 거리** — 그 단위의 `W<n>`(아래 "2회독 볼 거리"). 파트를 나눠 읽는 단위는 파트가 겹치는 차례에 붙는다. 생활상 거리는 2 · 3층이면 "이 층은 생활상을 하지 않는다"가 붙는다.
2. **정체 볼 줄** — 그 단위의 미상 이름표 줄(`???` · `남자의 목소리` …, `speaker_class = '미상'`)을 씬 · 이름표별 줄 번호로. `???`는 매번 다른 사람일 수 있어 기계로 누구에게도 잇지 않는다 —
   2회독이 씬마다 읽어 정체를 정하고 암시 언급 `speaker: true`(근거 = 그 씬의 그 `???` 줄들)로 적는다. 이미 적은 줄 수가 함께 나온다. 파트를 나눠 읽는 단위는 단위 전체를 보인다.
3. **되짚기** — 앞 2회독 세션이 2회독 파일 `revisit`(`where`에 이 단위 키 · 씬)으로 넘긴 열린 메모.
4. **1회독 기록과 그 뒤** — 이 단위의 1회독 파일(2회독 파트와 겹치는 것 — 1회독과 파트 묶음이 달라도 된다)의 사실 · 의문 · 사건 · 시점 전부, 읽은 순서. `✓` 확정 · `(추정)` = 바로잡기에서 다시 볼 1회독 추정.
   - 사실 줄 끝: 뒤 기록 `+단위(F12-2)` 다시 드러냄 · `⟲단위(F12-3)→F30` 뒤집음 — 뒤집음의 새 사실은 다음 줄 `  ⟲ F30 …`에 문장째.
   - 의문 줄 끝: 상태(열림 · 일부 · 풀림), 다음 줄들 `  → 풀림 F30 (Q3-2 단위): 답 문장` — **던진 의문의 답**(뒤에 밝혀지는 것)을 문장째.
   - 사건 줄: 이 단위가 푼 앞 의문 · 다시 드러낸 앞 사실을 그 문장과 함께.
5. **줄기** — 이 단위 기록이 곧바로 든 떡밥 줄기(의문 · 답 · 줄기 facts · 그 사건). about으로만 걸친 줄기는 ID만(handoff/threads.md).

**줄기 절** — 세션에서 걸친 줄기마다 한 번: 줄기 문장, 든 의문 전부(상태 · 답이 된 사실 ID — 이번 세션 단위의 의문은 "위 단위 절"로 줄인다),
**결말** = 곧바로 든 사실 가운데 출시순 뒤쪽 8건(`THREAD_FACTS_MAX` — 나머지는 threads.md), 줄기 관계(`G<n>`).

    정체 연결의 근거 줄도 쓰지 않는다 — 근거 줄은 정체를 보여 주는 줄일 뿐 그 인물이 말한 줄이라는 보장이 없다(L8의 근거 줄은 뉴스를 읽는 `남자의 목소리`다 — 2026-10-05 고침).
  - `A = B`(이명 · 숨은 정체 — 모더니아 = 마리안, 피라 = 라피 …)는 **같은 인물 무리를 대상 하나로 친다**: 줄마다 무리의 대표(연결의 b 쪽 — a로 나온 적 없는 것) 하나로 세고,
    사실의 `about`도 대표로 바꿔 센다. 이명마다 따로 세면 사실이 적은 이명(트윙클 · 피라)의 사실이 점수 앞자리를 차지한다. 머리줄에 무리를 `마리안 = 모더니아`로 보인다.
- **지금까지 2회독 기록** — 원문 인물의 인물 변화(`D`) 전부(인물별 — 기준이 이미 있는 측면에 기준을 또 세우지 않게), `about`이 원문 대상과 겹치는 생활상(`U` — 1층 세션에만. 2 · 3층은 생활상을 적지 않아 싣지 않는다, C1).

  ① 인물 × 측면마다 기준과 마지막 변화만 문장째, 사이 변화는 ID → ② 생활상은 뒤(최근)부터 문장째, 앞은 ID만 → ③ 한 줄을 짧게(근거 없이 60자)
  → ④ 측면마다 마지막 하나만(40자 — 변화가 있으면 마지막 변화, 없으면 기준), 앞 기록은 인물마다 ID 한 줄 → ⑤ 원문 줄 수가 적은 인물부터 한 줄(`### 이름 — n건: 측면 ID·ID / …`)로.

  관계는 상대(`with`)마다 다른 측면으로 친다. ⑤에서도 측면마다 기록 ID가 남아 기준이 있는 측면을 알 수 있다 — 문장은 `records.mjs review D…`.
  줄기 절을 끝까지 줄여도 먼저 읽을 것이 넘으면 이 절을 더 줄인다. 이 절이 있는 만큼 앞뒤 사실의 최소 몫(FOCUS_MIN 8,000자)을 줄인다(4,000자까지).

## 2회독 볼 거리 — `annotations/watch.json` (B1b)

1회독은 드러난 것만 적고 행동 · 묘사로 흘린 복선 · 감정선 · 뜻이 불분명한 말은 "2회독 몫"으로 넘겼다(docs/history/reading.md R 인계 · 기록 파일 이유 · 요약). 그것을 단위별 항목으로 옮긴 파일이다 —
2회독 인계 파일이 그 단위 차례에 "볼 거리"로 붙인다. **작업 메모라 후보가 아니다**(상태 · 검토 없음, 결과로 쓰지 않는다 — 되짚기 메모처럼). 2회독 세션은 그 대목을 읽고 2회독 기록(`I` · `E` · `D` · `U`)이나
바로잡기로 남기거나, 남길 것이 없으면 그냥 넘어간다(닫기 표시는 없다 — 그 단위의 2회독 파일이 생기면 본 것이다).

```json
{ "id": "W17", "unit": "char:162", "kind": "언급", "text": "미하라의 '그 사람'(이름이 가려진 '■■■은') — 지휘관으로 보이지만 원문은 이름을 대지 않는다",
  "evidence": [{ "scene": "ep:d_nikke_mihara_bondingchain_04", "lines": [66] }], "points": ["Q246"], "from": "R62 인계 · char.162.json Q246 이유" }
```

| 칸 | 필수 | 무엇 |
|---|---|---|
| `id` | ○ | `W<n>` — 전체에서 하나(`records.mjs next`) |
| `unit` | ○ | 읽기 단위 키 |
| `parts` | | 파트를 나눠 읽는 단위의 **1회독** 파트(`"4-6"`) — 2회독 파트와 겹치는 차례에 붙는다. 없으면 그 단위의 모든 파트(경고) |
| `kind` | ○ | 무엇으로 적을 거리인가 — `언급`(이름 없이 가리킴 · 누구의 말인가) · `떡밥`(암시 · 재언급 · 불분명한 말 · 원문이 잇지 않은 연결) · `변화`(감정선 · 관계 · 신념) · `생활상` |
| `text` | ○ | 무엇을 볼지 한 문장(200자 안쪽) — 1회독 메모의 말을 살린다 |
| `evidence` | | `[{ "scene", "lines" }]` — 메모가 씬만 가리키면 `lines`는 없어도 된다. 씬은 그 단위 안 |
| `points` | | 이어 볼 1회독 기록(`F` · `Q` · 사건 · `J`) |
| `from` | ○ | 출처 — `R62 인계` · `char.162.json Q246 이유` |

- B1b가 82건을 옮겼다(docs/history/reading.md R41–R99 인계의 판단 메모 + 기록 파일 18곳, 겹치는 것은 하나로). 메모에 단위가 없으면 1회독 요약 · 원문 이름표로 단위를 정했다(예: R97의 장화 · 홍련 · 레드 슈즈 → ch48).
- 2회독 세션이 아직 읽지 않은 단위에 넘길 것은 볼 거리가 아니라 2회독 파일 `revisit`(`where`)으로 넘긴다. 볼 거리에 더하는 것은 1회독 쪽에서 넘길 것이 새로 생길 때(신작 1회독 · 바로잡기)뿐이다.

## 작중 연대기 — 시점 기록 구조화 (X1b)

시점 기록(`S`)의 문장을 관계 · 기준으로 구조화한 칸. 작중 자리 계산은 `tools/views/chrono.mjs`(규칙은 머리말), 결과는 `data/views/timeline/chrono.csv`(단위별) ·
`chrono-pieces.csv`(조각별) · report.md, 질의는 `node tools/query.mjs chrono <단위 | ch20 | @기준점>`. 화면은 [docs/views.md](views.md) 화면 6.
X1b(2026-10-08)에 Claude가 1회독 파일의 394건(2회독 바로잡기 포함)을 모두 구조화해 확정했다 — 해석이라 기준이 바뀌면(사용자 피드백) Claude가 다시 구조화한다.
새 시점 기록(2회독 바로잡기 · 신작 N3)은 처음부터 이 칸을 같이 쓴다 — `at`이 없으면 검증기가 경고한다.

| 칸 | 뜻 |
|---|---|
| `subject` | 무엇의 때인가. 없으면 `kind`로 — `기준점` → `단위`(이 단위의 '지금'), `회상` → `구간`(근거 장면). `구간`은 기준점이어도 단위의 '지금'과 다른 때(af의 다른 줄거리 · 단위 안 다른 날 · 문서 속 사건 · 액자 바깥). `@…`(시대 기준점)은 기준점 자체의 때를 말하는 기록('갓데스 폴은 70년 전') — 계산은 확인만 한다 |
| `at` | `[[관계, 기준, 간격?], …]` — 모두 만족(교집합). 간격은 표시용 글('3주' · '70년' · '며칠'). 관계가 없으면 `[]`(계절 · 하루만 있거나 다른 단위와의 앞뒤가 원문에 없다) |
| `years` | 지금(CH.00 무렵)에서 몇 년 전인지 어림수 — 수 또는 `[처음, 끝]`. 원문의 수('15년 전' · '방주 밀봉 50년쯤 뒤')를 시대 기준점 연수로 셈해 적는다. 수가 없으면('몇 년' · '수십 년') 쓰지 않는다. 관계만으로 자리가 좁혀지면 쓰지 않아도 된다 |

- **관계** — `직후` · `뒤` · `직전` · `전` · `동시` · `중`(그 기준 동안 — 계산은 동시와 같다) · `무렵`(앞뒤 한 칸).
  '바로 앞'은 직전, '다음 날 · 며칠 · 몇 시간 뒤'는 직후, '몇 주 · 몇 달 · 몇 년 뒤'는 뒤 + 간격. 'CH.32–34 무렵'은 `뒤 ch31` · `전 ch35`, 'CH.40–41 무렵'은 `무렵 ch40` · `무렵 ch41`.
  'A 뒤 · B 전'처럼 경계를 둘 말하면 둘 다. 긴 회상 구간('침공 직후부터 40년 전까지')은 구간 전체를 감싸는 경계로 — 앞 끝은 `뒤`, 뒤 끝은 `전` · `years [처음, 끝]`.
- **기준** — 단위 키 · 씬 ID · 시점 기록 ID(`S<n>` — subject 단위면 그 단위, 구간이면 그 조각) · 시대 기준점(`@…`).
  사실(`F`) · 대상(`person:` …)은 기준으로 쓰지 않는다 — 그 일이 일어난 단위 · 씬 · 시대 기준점으로 바꾼다(`ref`는 그대로 둔다).
  조각만 있는 단위(`fl:ark_ranger` · `event_overthehorizon`처럼 '지금'이 하나가 아닌 단위)를 기준으로 삼을 때는 그 조각의 `S<n>`을 쓴다.
  자기 단위 키는 subject가 `구간`일 때만(회상 '15년 전' — 그 단위의 지금 기준). subject `단위`가 자기 단위를 가리키면 오류다.
- **시대 기준점** — `annotations/chronology.json` `eras`: 차례(과거 → 지금) · `years`(어림 연수, 원문에 수가 없으면 null) · `basis`(근거 시점 기록) · `reason`. 메인 챕터 앞에 놓여 작중 축을 이룬다.
  지금 8 — 랩쳐 침공(100년 전) → 갓데스 투입(98) → 궤도 엘리베이터 강습(97) → 아크 가디언 작전(95) → 방주 밀봉(95) → 1차 지상 탈환전(—) → 갓데스 폴(70) → 2차 지상 탈환전(60) → ch00.
  더할 때는 여러 기록이 그 사건을 기준으로 삼을 때만(X1b — 방주 이주 결정은 강습과 붙어 있어 따로 두지 않았다). Claude가 확정한다(사용자는 기준에 피드백).
- **가르기**(chrono.mjs) — 판별(한 점 무렵 · 이웃한 두 점 사이) · 범위(경계가 있으나 더 넓음 — 'CH.15 뒤'처럼 한쪽만 아는 것 포함) · 상대(다른 단위와의 앞뒤만 있고 작중 축에 닿지 않음) · 불명(관계 없음).
  메인 챕터는 번호 순에 고정했다(가정 — 병행 줄거리인 ch43 · ch44는 "메인 챕터끼리"로 따로 보인다). 단위는 자기 관계 → 기준점 조각들(여러 자리) → 남이 이 단위를 기준으로 삼은 관계 →
  기록이 모두 회상이면 회상 조각(과거 문서 · 옛이야기) 순으로 가른다. 모순(빈 자리 · 고정점 어김) · 순환은 report.md에 뜬다 — X1b 끝에 0.
- **검증기**(`records.mjs check`) — subject · 관계 · 기준(모르는 기준점 · 없는 · 기각된 · 자기 기록, 모르는 단위 · 씬) · years 꼴, subject 단위의 자기 단위 기준(오류), `at` 없음(경고).
- **견주기**(X1d) — 이 자리를 공개 자리와 견준 어긋남(과거 · 앞 · 맞음 · 걸침 · 뒤) · 작중 순서(화면 6 시안) · 인물 변화의 작중 시점 · 공개 단계의 작중 축은 기록이 아니라 계산이다
  (`tools/views/chrono-order.mjs` → chrono.csv 어긋남 칸 · chrono-order.csv · chrono-changes.csv · chrono.md). 새 기록 칸은 없다 — 시점 기록 · 좁힘을 고치면 다시 뽑힌다.

### 좁힘 — `annotations/chronology.json` `units` · `codes` (X1c)

시점 기록이 없거나 모자란 단위(상대 · 불명 · 한쪽만 아는 범위)를 다른 기록(인물 상태 · 사건 · 인물 변화) · 모습 코드로 좁힌 결과. 원문에서 나온 시점 기록과 섞지 않으려고
1회독 파일이 아니라 `chronology.json`에 둔다. Claude가 확정한다(사용자는 기준에 피드백 — CLAUDE.md "일하는 법").

| 칸 | 뜻 |
|---|---|
| `unit` | 읽기 단위 키. 메인 챕터는 안 된다(작중 축의 고정점) |
| `piece` | (X1c-3) 조각 하나에 더할 때만 — 그 단위의 구간 시점 기록 ID(`S…`, subject 구간 · 회상). 없으면 단위의 '지금'에 더한다. 한 단위에 '지금' 항목과 조각 항목을 따로 둘 수 있다(조각마다 하나) |
| `at` · `years` | 시점 기록과 같은 꼴 — 그 단위의 '지금'(단위 노드, `piece`가 있으면 그 조각)에 더한다. `[]` = 단서 없음 — 검토했고 더 좁힐 것이 없다(자리는 그대로, 기록이 없으면 시점 불명) |
| `basis` | 근거 — 기록 ID(`F` · `D` · `S` …) · `code:<모습 코드>` · 씬 ID(`#줄`) · 단위 키. `at`이 있으면 필수 |
| `reason` · `confidence` · `session` | 이유 · `확실`/`추정` · 정한 항목(`X1c-1` …) |

- **판단 원칙**(X1c-1, Claude):
  - 하한 — 첫 만남 · 생긴 때: 단위의 '지금'이 메인 CH.N에서 처음 만난 인물을 이미 아는 사이로 다루거나(그 인물이 지휘관을 알아본다 · 지휘관이 찾아간다)
    CH.N에서 생긴 상태(새 무장 · 소속 · 몸)를 이미 있는 것으로 다루면 `뒤 chN`. 1회독 S370(char:200 — 달란트를 이미 안다 → CH.15 뒤)과 같은 논리다.
    메인에서 이름만 나오고 직접 만나는 것은 그 단위가 처음이면(차임 · 아인 · 루주) 하한이 아니다. 이름이 언급되는 것만으로도(트로니가 일레그 이야기를 함) 하한이 아니다.
  - 상한 — 아직 안 바뀐 상태: 메인 CH.N에서 바뀌어 돌아오지 않는 상태(갇힘 · 죽음 · 소속)를 바뀌기 전 모습으로 그리면 `전 chN`(D-OUTSIDERS — 크로우가 자유롭다, CH.24에 갇힘).
    공개 순서만으로(그 단위가 CH.N보다 먼저 나왔다는 것만으로) 상한을 두지 않는다 — 공개 순서와 작중 순서를 섞지 않는다(어긋남은 X1d가 본다).
  - 끊긴 상태: 메인 CH.12–15에 라플라스 · 드레이크가 침식 · 콜드 슬립이다 — 둘이 멀쩡히 움직이면 짧은 틈(CH.11–12)보다 CH.15 뒤로 본다.
  - 누구에게나 걸리는 하한(지휘관 부임 · 카운터스 결성 = CH.00–01)은 적지 않는다 — '지금' 어딘가일 뿐인 단위는 `at: []`(시점 불명)으로 둔다.
  - 시점 기록이 이미 있는 단위는 그보다 더 좁히는 관계만 더하고, 없으면 `at: []`로 검토만 표시한다. 이벤트에 기대는 호감도 묶음은 이벤트가 축에 닿으면 함께 내려온다.
- **판단 원칙 더하기**(X1c-2a, 호감도 — Claude):
  - 아는 사이의 증거 — 그 인물이 지휘관을 호칭 · 별명으로 맞거나('점장님' · '신참' · '꼴통 후배' · '꽃님' · '버드 보이' · '형님' · '어머, 지휘관도 오셨군요') 지휘관이 이름으로 찾아간다('맥스웰을?' · '엑시아를 찾아가봐야겠다').
    가게 · 탈것 손님처럼 지휘관을 알아보는 말이 없으면 하한으로 쓰지 않는다(char:141 카페 스위티 · 도라, char:212 슈가의 '마차').
  - 전초기지 배속(CH.02)은 지휘관이 사는 곳일 뿐이라 CH.00–01처럼 적지 않는다. CH.02 뒷이야기에서 처음 만난 인물(유니 · 미하라 · 슈엔)을 아는 사이로 다루면 `뒤 ch02`를 적는다(event_cherryblossom과 같이).
  - 지휘관이 나오지 않는 단위(콜라보 일부 — char:820 · 821 · 831 · 833 …)에는 첫 만남 하한이 걸리지 않는다. 인물은 메인에 처음 나오기 전부터 있었다.
  - 첫 대면이 메인이 아닌 단위면 그 단위 키를 기준으로 — 플로라는 CH.27에서 통신으로만 말하고 처음 얼굴을 마주한 것은 char:411(S190)이라 '꽃님'으로 맞는 단위는 `뒤 char:411`.
  - 다른 단위의 일을 지난 일로 말하면 그 단위 키 기준 `뒤`(앵커 — 헬름의 선상 파티 불가사리 → `뒤 char:352`, 노이즈 — 볼륨 · 아리아를 '프로듀싱' → `뒤 char:431` · `뒤 char:432`, 히메노 — 드레이크 · 파워가 한패 → `뒤 char:801`). 둘 다 축에 닿지 않으면 상대로 남는다.
  - 모습 코드가 한 단위 안에서 일부러 갈리면 상한이 된다 — 모리 편(char:590)은 본문 내내 `rapi`이고 '그로부터 긴 시간이 흐른 후' 끝 장면만 `rapi_red`라 본문을 `전 ch34`로 봤다(메인은 CH.34 끝부터 `rapi_red`만 쓴다).
    기본 코드(`rapi` · `laplace`)만 쓴 것으로는 상한을 두지 않는다 — 시점과 무관하게 기본 모습을 쓰기도 한다(char:94의 라플라스).
  - 레오나 곁의 티미는 event_lionheart 하한이 아니다 — 티미는 새끼 때부터 보호소에서 자랐다(F1255 · D1521). 갱생관의 마나는 M.M.R. 마나와 같은 인물인지 원문이 말하지 않아 쓰지 않는다.
- **판단 원칙 더하기**(X1c-2b, 호감도 한쪽 범위 — Claude):
  - 상한으로 쓴 돌아오지 않는 메인의 변화 — 크로우 수감(CH.24 D293, 뒤로는 이름 · 회상만) · 유니 수감과 언어 능력 제거(CH.24 D292 — 그 뒤로는 '우'만 말한다, side:wordless S174) ·
    파피용의 에덴 잔류(CH.21 D218 — CH.44 · 46에도 에덴) · 테러 조직 엔터 헤븐의 소멸(CH.39 무렵 — d_main_39_af_03, fl:enter_heaven) · 신데렐라 · 그레이브가 세이렌을 찾아 떠남(CH.36 끝) · 스노우 화이트 수리(fl:ark_guardian 전, D973).
    그 인물 · 조직이 바뀌기 전 모습으로 '지금' 움직이면 `전`을 둔다. 회상 · 지나간 일(AFX 추모식 · 엔터 헤븐에 대비한 점검)은 쓰지 않는다.
  - 마지막 챕터 무렵의 변화(CH.46–48 — 도로시의 사라짐 D1348 · 나유타 꼭두각시 · 장화)는 이야기가 이어지며 돌아올 수 있어 상한으로 쓰지 않는다. 떠난 때를 모르는 상태(목단이 모란회를 떠나 있던 때)도 쓰지 않는다.
  - 상한이 끝 장면과 겹칠 수 있으면 한 칸 뒤로 둔다 — 그레이브 편의 퇴원 날 떠남이 CH.36 끝의 떠남일 수 있어 `전 ch37`.
  - CH.12–15 콜드 슬립 원칙(라플라스 · 드레이크)을 맥스웰에도 쓴다(D96 · D124) — CH.11에 처음 만난 메티스를 이미 아는 단위는 `뒤 ch15`.
  - '기억을 되찾았다' 같은 말은 어느 회복인지 원문으로 가린다 — 스노우 화이트의 언니 기억은 event_goddessfall1(D953)이고 CH.44(D1038)의 모든 기억 회복이 아니다.
    '최근 코인 러시에서 열린 이벤트'처럼 가리키는 이벤트를 원문에서 특정할 수 없으면 쓰지 않는다(char:405).
  - 이벤트 · 콜라보 중의 호감도(`중 event_…`)는 이벤트의 자리를 따른다 — 이벤트 밖 단서가 없으면 `at: []`. 상한도 이벤트 쪽(X1c-1)에서 온다.
  - 앞 항목(X1c-2a)의 항목에 관계를 더할 때는 그 항목을 고치고 session을 고친 항목으로, `note`에 나눈 몫을 적는다(char:160 · 161 — '하한은 X1c-2a, 상한은 X1c-2b').
- **판단 원칙 더하기**(X1c-3, 서브퀘스트 · 유실물 · 사이드 — Claude):
  - 연작 서브퀘스트 — 원문이 앞 편의 일을 가리키면('다시 연락' · '지난번 술병' · '두 번째 지도' · '또 이 계정으로') `뒤 <앞 편>`. 다른 연작의 일이면 그 편(MMR지킴이 — '얼마 전 이안 맥스의 의뢰' → `뒤 sub:핸섬_커맨더_01`).
    연작의 한 편이 메인에 닿으면 앞뒤 편이 함께 좁혀진다(랩칠리언 06 `전 ch27` → 00–05, 관짝이 02 `전 ch33` → 00 · 01 · 거울 공주 01). 앞 편을 가리키지 않는 첫 편은 `at: []`.
  - 지휘관이 '이름난' 사람이라는 말(가장 동경하는 인물 1위 · 요즘 인기가 뜨거운 · 방주의 떠오르는 신성)은 쓰지 않는다 — 언제부터인지 메인 기록이 정하지 않는다. 사관학교 졸업 축하도 상한이 아니다.
  - 아는 사이의 증거는 호감도와 같다(X1c-2a) — 지휘관이 계정 주인을 알아봄(철도로GO에 '둘한테도 안부' → 인피니티 레일 CH.13), 이름으로 요청함('프로토콜에 분석을 요청해 보자' → 엑시아 CH.07).
    그 서브퀘스트에서 처음 나오는 인물(리타 · 센티 · 율리아)은 하한이 아니고, 첫 만남이 메인이 아닌 인물(폴리 — char:180)도 쓰지 않는다. 선택지로만 드러나는 앎(시지 패러리스)은 쓰지 않는다.
  - 1회독 시점 기록이 연작 모두를 말하는데 첫 편에만 붙어 있으면 나머지 편에 같은 관계를 둔다(에덴 Notice — S64 '세 편은 CH.21 무렵').
  - 시점 기록이 회상뿐이라 회상 자리가 단위 자리로 쓰였는데 그 편에 지금 장면이 있으면 좁힘으로 지금을 둔다(핸섬 커맨더 2 — 23–12년 전 회상 → 1편 뒤).
  - 유실물 문서의 '지금'은 문서가 쓰인 때 — 내용의 때로 둔다. 침공을 처음 겪는 일상(장보기 목록 · '외계인' 방송)은 `무렵` · `직후 @랩쳐_침공`, 랩쳐 · 니케 실험이 있으면 `뒤 @랩쳐_침공`, 갓데스를 동경하거나 갓데스가 싸우면 `뒤 @갓데스_투입`.
    밀봉 뒤 지상에 남은 사람도 있어 지상 생활만으로는 `전 @방주_밀봉`을 두지 않는다 — 갓데스 스쿼드의 전장(승리의 날개 호)처럼 밀봉 뒤 흩어진 것이 나올 때만(추정).
  - 메인 사건 전의 문서 — 메인 CH.N이 그 결과를 이미 있는 것으로 보이면 `전 chN`: 하모니 큐브가 솟게 한 하얀 건물(CH.30) · 개발 중인 말뚝(CH.31 실전) · 수정에 덮인 유리 구두(CH.32에 되찾음) · 직계에게 복수를 다짐한 첫 만남(CH.33에 지난 일로 말함) ·
    '남자의 정수'를 구하라는 용광로 메모(CH.41에 지휘관의 정수로 퀸을 만듦) · 웨일리 뱃속의 '그 아이'(CH.39에 나유타는 이미 그 인연으로 웨일리 위에 있음). 같은 대상인지 원문이 말하지 않으면 추정.
    그 문서의 대상이 언제부터 있었는지 모르는 것(수정 랩쳐 · 포비스트의 알 실험 · 에덴 같은 불빛 건물)과 지시가 앞의 것인지 뒤의 꾸중인지 모르는 것(할 일 목록)은 `at: []`.
  - 조각(한쪽만 아는 구간 시점 기록)은 `piece`로 반대쪽 경계를 준다 — 같은 이야기 안 다음 조각(eden_spear S264 `전 S265`), 지금 성인인 인물이 아이인 때(PRETTY STAR 끝 — 버닝엄 → `전 ch00`),
    메인에 이미 그 뒤 모습으로 나오는 인물(WHITE MEMORY 끝 — CH.06의 스노우 화이트는 이미 헬레틱을 쫓는 필그림 → `전 ch06`). 원문 시점 기록(1회독 파일)은 고치지 않는다.
- **모습 코드**(`codes`) — 이름표와 별개로 띄우는 모습(`lines.speaker_id`) 가운데 시점과 이어진 것만: `code` · `person` · `meaning` · `first`(읽는 순서로 처음 쓰인 줄) · `at`(그 코드가 말하는 때) · `basis` · `reason`.
  지금 10 — `marian_p`(CH.13 뒤) · `rapi_red`(CH.34 뒤) · `laplace_p` · `drake_p` · `maxwell_p`(새 무장, CH.38부터) · `anis_i`(CH.42 뒤) · `neon_v`(CH.44 뒤) · 갓데스 시절 `snowwhite_o` · `rapunzel_o` · `hongryeon_o`.
  계산에는 넣지 않고 좁힘의 근거(`code:<코드>`)로만 쓴다(이벤트 의상처럼 시점과 무관한 코드가 있다). 의상(`_s` · `_c` · `_w` · `_m` …) · 통신창(`_op` …) 코드는 넣지 않았다.
  한 이벤트의 과거 장면에만 쓰인 코드(라피의 `youngrapi` · `rapi_h` · `rapi_m`, 아니스의 `anis_human` · `anis_idol` — STAR ANIS · FOOTSTEP)는 다른 단위를 좁히지 않아 뺐다.
- **단서표** — `tools/views/chrono-clues.mjs` → `data/views/timeline/chrono-clues.csv`(메인 밖 단위마다 시점 코드 · 메인에서 처음 나온 대상 · 메인에서 소속 · 신체 · 기억이 바뀐 인물),
  `node tools/query.mjs chrono <단위>`의 "단서". 기계적 신호라 해석이 아니다 — 위 원칙으로 Claude가 본다(메인에서 처음 나왔다고 작중에서 그때 생긴 것은 아니다).
- **계산**(chrono.mjs) — 좁힘은 단위 노드에 관계를 더한다. via에 `좁힘`(자기 시점 기록과 함께면 `단위 · 좁힘`)이 붙고, chrono.csv `narrow`(관계 글 · '단서 없음') · `narrow_confidence`. `piece` 항목은 그 조각 노드에 더하고 chrono-pieces.csv `narrow` · `narrow_confidence`에 뜬다. 시점 기록과 부딪치면 모순으로 뜬다.
- **검증기** — unit(읽기 순서 · 메인 아님 · 겹침) · piece(그 단위의 살아 있는 구간 시점 기록 · 조각마다 하나) · at 꼴 · 자기 단위 기준 · basis(있는 기록 · codes에 있는 코드 · 씬 · 줄 꼴) · reason · confidence · session, codes의 code(원문에 있음) · person(사전) · first.

## 소속 기록 — `annotations/affiliations.json` (W12, 2026-10-10)

인물 옆 기업 · 스쿼드 마크(사이트 — docs/views.md "소속 마크")의 근거. 소속도 스토리 정보다(사용자). 두 갈래로 나눈다:

- **실장 니케의 지금 소속은 기록하지 않는다** — 게임 데이터(roledata `corporation` · `squad_detail`, docs/data-sources.md 10절)에서 `tools/blabla/marks.mjs`가 계산한다. 공개 자리만 아래 "게임 소속의 공개 자리"(W12d).
  파일 `game`은 게임 코드 → 사전 조직 ID 대응만 둔다: `corporations`(ELYSION …) · `squads`(roledata `squad` 코드 — Counters …). 원문 범위 안에 이름이 0건이면 `null`(사전에 못 넣는다 — 사이트는 게임 이름만 보인다).
  게임에 새 스쿼드가 생기면 `orgs.mjs`가 ⚠로 알린다 — 사전에 있으면 그 ID, 범위 안에 나오면 orgs.json에 더하고 ID, 아니면 `null`. 테스트(`tests/affiliations.test.mjs`)가 빠진 코드를 잡는다.
- **해석 기록(T)** — 실장 밖 인물의 소속(W12b)과 작중 소속 이동(W12c). 후보로 쓰고 Claude가 확정 · 기각한다(CLAUDE.md "해석이 필요한 기록").

```json
{ "session": "W12b", "by": "claude", "date": "2026-10-10", "game": { "corporations": { … }, "squads": { … } },
  "affiliations": [
    { "id": "T1", "person": "person:엔더슨", "org": "org:중앙_정부", "act": "소속", "role": "부사령관", "evidence": [{ "scene": "d_main_…", "lines": [12] }],
      "reason": "…", "confidence": "확실", "status": "후보" },
    { "id": "T60", "person": "person:…", "org": "org:…", "act": "이탈", "records": ["D1234"], "evidence": [{ "scene": "…", "lines": [40] }], "reason": "…", "confidence": "추정", "status": "후보" }
  ] }
```

| 칸 | 필수 | 뜻 |
|---|---|---|
| `id` | ✓ | `T<n>` — 한 번 붙이면 바꾸지 않는다(`node tools/records.mjs next` 끝의 "소속") |
| `person` | ✓ | 인물 대상 ID(사전). 같은 인물 묶음은 대표 ID 하나로(이명 · 이름표가 달라도 — 인물 변화 D와 같다) |
| `org` | ✓ | 조직 대상 ID(`org:` — annotations/dictionary/orgs.json). 없으면 사전에 먼저 더한다(docs/schema.md "비인물 사전" — 범위 안 1줄 이상) |
| `act` | ✓ | `소속`(그 자리에서 드러난 소속 — 처음부터 그랬다) · `합류`(그 자리에서 들어감) · `이탈`(그 자리에서 나감 — 해체 · 탈퇴 · 추방 · 죽음으로 끝남) · `지난 소속`(그 자리에서 드러난, 이야기의 지금보다 앞서 끝난 소속 — W12e, 아래) |
| `role` | | 조직 안 자리 — 짧게(30자 안쪽): `부사령관` · `분대장` · `CEO` |
| `evidence` | ✓ | 그 소속이 **드러난** 씬 · 줄. 첫 근거 씬의 단위가 이 기록의 공개 자리(사이트 스포일러 컷오프)다 — 처음 드러난 곳을 든다 |
| `records` | | 근거 기록 — 인물 변화 `D`(aspect `소속`) · 사실 `F`. 이동(합류 · 이탈)은 그 변화 D를 단다(남의 변화면 경고) |
| `reason` · `confidence` · `status` · `by` · `session` · `note` · `reviews` | | 후보 공통 칸(위 "상태 · 검토") |

**시점별 소속 규칙 — 합치기**(화면 — `fmt.orgsAt`, 사용자 C안 2026-10-10 · W12d): 게임 소속(실장 니케)은 **늘 남긴다** — 공개 자리(아래)를 지났으면 보인다.
그 위에 인물의 확정 T를 그 자리(여기까지 읽음)까지 공개 순으로 쌓는다(소속 · 합류 → 들어 있음, 이탈 → 나감). 조직마다 마지막 기록이 이탈이면 게임 소속이어도 뺀다(다시 합류하면 돌아온다).
기록이 다루지 않는 게임 소속은 그대로, 기록에만 있는 조직은 더한다. 같은 조직이 둘 다면 칩 하나(게임 소속 자리, 기록의 `role`을 붙임). 전부 보기 = 게임 소속 전부 + 기록 전부.
그래서 이제 T를 쓰려고 그 인물의 소속을 처음부터 다 적을 필요는 없다(W12c까지의 규칙 — 그때는 T가 하나라도 있으면 게임 소속을 덮었다).
작중 시점 순 정렬은 하지 않는다(공개 순 — 독자가 안 순서). 기업(`kind` 기업)이 앞, 나머지는 스쿼드 칸으로 보인다.

**게임 소속의 공개 자리**(W12d — 사용자: 게임 소속 마크에도 스포일러 컷오프): 실장 니케 × 게임 소속 쌍마다 그 소속이 **그 인물의 소속으로 처음 드러나는 자리**를 읽어야 보인다. export가 `orgs[].tick`으로 계산한다:
- 다음 가운데 이른 것: ① 그 판의 출시 — 호감도 단위 `char:<rid>`의 공개 자리(게임 프로필에 기업 · 스쿼드가 보이므로 출시가 곧 공개다. 기계적, 기록하지 않는다),
  ② 그 (인물, 조직)의 확정 T(`소속` · `합류`)의 공개 자리 — 출시보다 앞서 원문에서 드러난 곳은 `act 소속` T로 적는다(해석 기록 절차).
  호감도 단위가 없는 판 가운데 게임 시작 로스터(`game.launch.resource_ids` — 양산형 R 솔져 · 프로덕트 · iDoll 9판, 사용자 확인 2026-10-10)는 출시 자리를 맨 처음(`1`)으로 본다.
- 사전 대응이 `null`인 소속(원문 범위 안에 사전 조직 이름이 없음 — 올드 테일즈 · 자칭 특별수사대 · 앱노멀 · 리플레이스 · 헬레틱(사전에는 개념) …)은 ②가 없어 ① 출시다.
  (W12d에는 `0` = 늘이었다 — 모더니아 헬레틱이 CH.00부터 보여 W15b에서 고쳤다. 64쌍 → 출시: 게임 시작 로스터 9쌍은 `1`, 나머지는 그 판의 호감도 스토리.)
- 둘 다 없으면(호감도 단위가 없고 원문에서도 안 드러남) 칸이 비고 **전부 보기에서만** 보인다(판정 못 함 — 읽는 중에는 숨김). 2026-10-10 기준 0쌍.
- ② 후보 뽑기(기계): 조직 이름 줄(언급 DB `named` · `alias` — 사전의 다른 이름 포함, 필그림 ↔ 순례자)에서 ±2줄 안에 그 인물이 말하거나 이름이 나오는 자리 가운데 출시보다 이른 것.
  **판정 기준**(Claude, 스포일러 쪽으로 보수적 — 일찍 보이는 오류보다 늦게 보이는 오류가 낫다): 드러남 = 그 인물이 자기 소속을 말함('우리 메티스' · '쿠킹오일 스쿼드의 크러스트'),
  남이 그 인물을 그 조직으로 부르거나 소개함('미실리스 인더스트리 소속 니케 리타' · '필그림. 그레이브 얘기야'), 조직 구성원을 꼽는 줄에 그 인물이 듦('나, 도라, 얀을 포함한 달란트'),
  막 나타난 무리가 조직 이름을 대고 그 인물이 그 무리임이 줄에서 분명함(앱솔루트 강하 · 익스터너 합류 — 확신도 `추정`도 있다).

- 같은 인물 묶음의 대표 ID는 인물 변화 D와 같다(T15를 프리시아 → 프리티로 옮김). 다른 이름은 화면이 정체가 밝혀진 자리부터 대표의 기록을 빌려 보인다(docs/views.md "소속 마크").
- 장소이자 조직인 이름(에덴)은 사전에 `shares`로 조직 대상을 따로 둔다(docs/schema.md "비인물 사전") — `org:에덴`.

**지난 소속**(W12e, 사용자 2026-10-10 — 지난 소속도 적고 지금 소속과 나눠 흐린 마크로): 이야기의 지금까지 이어지지 않고 앞서 끝난 소속이 원문에서 드러나면 `act 지난 소속`(자리는 `role`).
- 공개 자리 = 그 과거가 원문에서 **처음 드러난 줄**(첫 근거 씬의 단위) — 그 전엔 아예 안 보인다. 소문 · 짐작('전직 리더라는 루머')은 드러남이 아니다.
- 지금 소속 계산(합치기)에 들지 않고, 게임 소속의 공개 자리 ②에도 안 쓰인다(② = `소속` · `합류`만). 화면은 지금 소속 뒤에 '전 소속'으로(docs/views.md "소속 마크").
- 이야기 안에서 나간 조직(마지막 기록이 `이탈`)도 화면에서는 전 소속이다 — 그 경우 이탈 T가 곧 근거라 `지난 소속`을 따로 적지 않는다. 이야기의 지금에 있던 소속이 나중에 끝나면(E.H.의 엔터 헤븐: ch22 대장 → ch39 '그랬지') `소속` + `이탈`로 적는다.
- 게임 소속(다른 판 포함)이 이야기 기준 지난 소속이면 그 조직의 `지난 소속` T를 두고, 화면은 그 게임 칩을 전 소속 칩으로 바꾼다(지금 다시 `소속` · `합류`한 기록이 없을 때) — 스노우 화이트 · 라푼젤 · 홍련 · 레드 후드의 갓데스(T103–T106, W12f에 `소속` → `지난 소속`, 사용자 2026-10-10).
- 그 밖에 지금 소속(게임 데이터 · 다른 판 · 기록)과 같은 조직이면 화면에 한 번만(지금 쪽). 다시 들어가면(미세스 미스 테트라 T135 → T42) 들어간 자리부터 지금 소속으로.
- 이야기의 지금에 없는 인물(죽은 갓데스 리더 릴리바이스 T10 등)은 회상이 곧 그 인물의 이야기라 `소속` 그대로 둔다. 니케가 되기 전의 소속(출신)은 지난 소속이다(T19 레드 슈즈를 W12e에 바꿈).
- 원문이 지난 소속이라고 분명할 때만 — 만든 곳 · 소유를 다투는 곳(신데렐라의 인류연합군 · V.T.C., T138 · T139 기각), 같은 조직이 게임 데이터 다른 판으로 이미 보이는 것은 새 T를 쓰지 않고 그 판의 공개 자리 T를 `지난 소속`으로 바꾼다(위 — T103–T106, W12f).
- W12e: T128–T137(지난 소속 8 · E.H. 소속 · 이탈) 확정, T138 · T139 기각, T19 소속 → 지난 소속. 목록은 SESSIONS.md W12e.

**쓰는 법** — 파일을 고친 뒤 `node tools/records.mjs check`(검증: 인물 · 조직 ID, act, 근거 씬 · 줄, records, game 대응 · 같은 (인물, 조직, act, 근거 씬) 겹침 경고) ·
`review 소속 --brief` · `set T3 T5 확정 --by claude --session W12b --note "…"`(고치기 `--text`는 없다 — 칸은 손으로 고치고 `set`으로 결정만) ·
`node tools/site/export.mjs --only common`(`targets.json` 인물 `affs`). 예시: [tests/fixtures/read1/_affiliations.json](../tests/fixtures/read1/_affiliations.json).

## 공개 개요 — `annotations/synopsis/<키>.json` (W8, 2026-10-10)

사이트에 싣는 스토리별 줄거리(사용자, 2026-10-10 — "사이트에 포함시킬 것"). 1회독 `summary` · `scenes`는 작업 메모라
씬 ID · 줄 번호 · 기록 ID · 세션 이름이 섞여 있고, 2회독 바로잡기 전의 오독이 남아 있을 수 있어 **그대로 내보내지 않는다**.
대신 단위마다 화면용 개요를 새로 써서 확정한 것만 싣는다. 도구는 `tools/synopsis.mjs`, 세션은 SESSIONS.md W9–W10(W8은 docs/history/analysis.md).

**무엇** — 읽기 단위(1회독 키 그대로)마다 하나, **481단위** — 메인 49 · 엘리베이터 1 · 이벤트 60 · 금서고 이벤트 23 · 사이드 5 · 이벤트 유실물 9 · 서브퀘스트 86 · 유실물 55 · 호감도 193.
1회독 파일은 485개지만 파트로 나눠 적은 단위(`event_staranis1` 2 · `fl:2x2_love_1ch` 3 · `fl:2x2_love_2ch` 2)도 개요는 하나다. 파일 이름은 1회독과 같은 규칙(`char:180` → `char.180.json`).

```json
{
  "unit": "ch00",
  "session": "W8",
  "by": "claude",
  "date": "2026-10-10",
  "logline": "추락한 수송기에서 살아난 신입 지휘관이 … 스쿼드 04-F를 맡는다.",
  "synopsis": "지상 작전 구역으로 향하던 수송기 BA-01이 … \n\n랑데부 포인트에서는 …",
  "scenes": [{ "scene": "d_main_01_01_s", "text": "수송기가 추락하고, …" }],
  "status": "확정",
  "reviews": [{ "decision": "확정", "by": "claude", "date": "2026-10-10", "session": "W8", "hash": "3a4f6f7ee3", "note": "…" }]
}
```

전체 예시: `annotations/synopsis/ch00.json`(메인) · `event_nocallerid.json`(이벤트 — 씬 13줄) · `char.180.json`(호감도 — 줄거리는 다섯 편 전체의 흐름, 편마다는 씬 한 줄).

| 칸 | 필수 | 뜻 |
|---|---|---|
| `unit` · `session` · `by` · `date` | ✓ | 1회독 기록과 같다. `session`은 W9 묶음 이름(`new`가 `_batches.json`에서 채운다) |
| `logline` | ✓ | 한 줄 소개 — 무슨 이야기인가. **80자 안쪽(넘으면 오류)**. 분류 카드 · 리더 맨 위 |
| `synopsis` | ✓ | 줄거리. 문단은 빈 줄(`\n\n`)로 나눈다. 길이(벗어나면 경고): 메인 300–1,000 · 이벤트 · 사이드 200–800 · 이벤트 유실물 · 엘리베이터 150–600 · 호감도 100–400(다섯 편 전체의 흐름) · 서브퀘스트 · 유실물 60–400 |
| `scenes` | | 씬 한 줄 `[{scene, text}]` — **100자 안쪽**. 씬이 여럿인 단위(`new`가 씬마다 빈 칸을 만든다)와 호감도(편마다 하나). 그 단위의 씬만, 한 번씩. 리더의 씬 칸 · 스토리의 씬 목록에 뜬다. 씬 하나짜리(서브퀘스트 대부분)는 비워 둔다 |
| `status` · `reviews` | ✓ | 해석 기록이라 `후보` → Claude가 단위마다 검토해 `확정`(CLAUDE.md "해석이 필요한 기록"). 확정 검토에는 내용 지문 `hash`가 붙는다 — 확정한 뒤 문장을 고치면 지문이 달라져 검사 오류 · 내보내기에서 빠짐이 되므로, 고쳤으면 다시 `set … 확정`. 사용자가 마지막으로 결정한 단위(`by: 사용자`)는 Claude가 바꾸지 않는다(`set`이 거절한다) |

**입력** — `node tools/synopsis.mjs new <단위>`가 찍는 입력 묶음: 장면(씬 ID · 제목 · 1회독 씬 한 줄) · 1회독 요약 · 사실 · 의문(이 단위에서 던짐) · 사건(앞 의문 · 사실이 여기서 풀림 · 드러남 · 뒤집힘, 원래 의문 문장과 답) ·
작중 시점 · 나오는 대상(1회독 메모) · 기각된 기록("쓰지 말 것") · 설정 오류 추정. 기록마다 `[추정 …]` · `[2회독에서 더함]` · `[2회독에서 고침 — 전: …]` 표시가 붙는다(고친 뒤 문장이 본문이다).
원문은 다시 읽지 않는 것이 기본이다. 요약이 모호하거나 기록과 어긋날 때만 그 씬을 읽는다(`read.mjs <씬> --num`, 세션당 2만 자 안쪽).

**쓰는 법**
1. **우리 문장으로** — 대사를 옮기거나 장면을 줄줄이 재현하지 않는다(줄거리 소개 · 비평 목적의 요약). 1회독 요약 문장도 그대로 옮기지 않고 화면용으로 다시 쓴다.
   따옴표는 작품 속 이름 · 용어 · 짧은 말(20자 안쪽)만, 개요 하나(한 줄 소개 · 줄거리 · 씬 한 줄 전부)에 두 번 이하. 게임의 대괄호 용어(`[협회]`)는 괄호 없이 써도 된다.
2. **스포일러 — 그 자리의 독자가 본 것만.** 출시순으로 그 단위까지 드러난 것만 쓴다. 뒤 단위에서 밝혀지는 정체 · 진실 · 결말 · 본명은 쓰지 않고,
   2회독에서 안 복선의 뜻("이것이 나중에 …의 복선")도 쓰지 않는다. 이야기가 열어 둔 물음(입력의 "의문")은 열린 채로 둔다 — 답을 짐작해 쓰지 않는다. 2회독 바로잡기는 그 단위의 오독 정정이라 반영한다.
3. **화면 말로** — 씬 ID · 단위 키 · 줄 번호 · 기록 ID(`F12` · `Q3`) · 세션 이름 · 확신도 표시 · 작업 말("2회독" · "되짚기")을 넣지 않는다. 장면을 가리킬 일은 `scenes`로.
   인물은 그 자리에서 불리던 이름(사전 표기)으로 쓴다. 지휘관은 "지휘관"(대명사는 피한다).
4. **기각된 사실에 기댄 문장은 고친다.** 1회독 추정(`[추정 …]`)은 "~라고 말한다" · "~에 따르면"처럼 누가 한 말인지로 쓴다.

**도구** — `tools/synopsis.mjs`(모델 `tools/synopsis/model.mjs` · 입력 `tools/synopsis/input.mjs`, 테스트 `tests/synopsis.test.mjs`)

```bash

node tools/synopsis.mjs new ch00              # 입력 묶음을 찍고, 개요 파일이 없으면 틀(후보 · 씬 한 줄 빈 칸)을 만든다
node tools/synopsis.mjs check [ch00 …] [--all]   # 검사 — 오류면 종료 코드 1. --all은 빠진 단위 · 확정 안 된 단위도 경고(W10)
node tools/synopsis.mjs set ch00 ch01 확정 --note "…"   # 확정 전에 검사를 돌려 오류가 있으면 확정하지 않는다(경고는 보이고 통과) · --session
```

경고: 줄거리 길이 범위 밖 · 씬 한 줄 100자 초과 · 따옴표 안 20자 초과 · 따옴표 세 번 이상 · 작업 말 · 원문과 20자 이상 겹침(공백 빼고 — `check-quotes`와 같은 해시) ·
**스포일러**(그 단위 뒤에 처음 나오는 이름 — 언급 DB의 이름표 · 이름 · 별칭이 처음 나오는 읽는 자리. 앞에 나온 더 긴 이름 속에 든 것 · 앞에 한글 음절이 붙어 낱말 속 글자인 것(하이브 속 이브) · 영문 낱말 속 글자(DIVA 속 IV) · 흔한 낱말(사라지다 속 사라 — `COMMON_WORDS`) 속에 든 것은 뺀다. 이름만 보므로 정체 · 진실은 쓰는 쪽이 본다). 같은 대상의 표기 갈래(점 · 가운뎃점 · 띄어쓰기 · 대소문자만 다른 것 — `ACPU` · `A.C.P.U.`)는 처음 나온 자리를 나눈다(W10). 세는 말 `마리`(`여섯 마리`)도 뺀다.
- 스포일러 경고는 판단이 필요할 수 있다(같은 이름의 다른 인물 등) — 맞는 이름이면 그대로 두고 `set`의 `--note`에 까닭을 적는다.

**사이트** — `tools/site/export/synopsis.mjs` → `site/data/synopsis.json`(`[{ key, logline, synopsis, scenes?{씬 ID: 한 줄} }]`, 읽는 순서). 확정 · 지문이 맞는 개요만, 1회독 `summary`는 읽지 않는다.

## 팬용 문장 — `annotations/blurbs/<키>.json` (W14, 2026-10-10)

화면의 분류 이유(리더 분류 칸 '이유') · 연대기 추정 이유(연대기 카드 '추정한 이유')는 판정 기록이라 딱딱하다(사용자, 2026-10-10).
판정 기록 원문(`order.json` units `reason` · `chrono.json` narrows `reason`)은 분석용으로 그대로 두고, **화면용 한두 문장을 따로 쓴다**.
확정 문장이 있으면 화면이 그것을(gate를 지났으면 `later`까지), 없거나 낡았으면 지금처럼 거른 판정 문장(`fmt.reasonText` · `fmt.dropClauses`)을 보인다 — 내보내기 `tools/site/export/blurbs.mjs` → `site/data/blurbs.json`(확정 · 고치지 않음 · 낡지 않은 칸만), 화면 규칙은 docs/views.md "팬용 문장(W14c)".
도구는 `tools/blurbs.mjs`, 세션은 SESSIONS.md W14.

**무엇** — 단위마다 파일 하나, 칸 둘:
- `why` 분류 이유 — 척추 밖 판정 단위 **421**(준필수 5 · 추천 47 · 참고 239 · 독립 130). 원본 `site/data/order.json` units.
- `when` 연대기 추정 이유 — 연대기 카드에 '추정한 이유'가 뜨는 단위 **93**(자리 있음 · 확신도 추정, `site/data/chrono.json` narrows — 카드와 같은 거름). 원본이 한 단위에 여럿이면 문장은 하나로 묶는다.

파일 이름은 1회독 · 공개 개요와 같은 규칙(`sub:세르반_03` → `sub.세르반_03.json`). 예시: `annotations/blurbs/sub.세르반_03.json` · `char.171.json`(when).

```json
{
  "unit": "sub:세르반_03",
  "why": {
    "text": "버닝엄 부사령관은 지휘관을 엔더슨 쪽 사람으로 보면서도, 정부군을 움직일 수 없는 아들 일만은 지휘관에게 맡긴다.",
    "later": "CH.44에서 버닝엄이 아들의 일로 지휘관을 믿는 까닭이 이 이야기다.",
    "gate": "ch44",
    "src": "c5b61d01bf",
    "session": "W14a", "by": "claude", "date": "2026-10-10",
    "status": "확정",
    "reviews": [{ "decision": "확정", "by": "claude", "date": "2026-10-10", "session": "W14a", "hash": "b9639def1a", "note": "…" }]
  }
}
```

| 칸 | 뜻 |
|---|---|
| `text` | 화면 문장. 권장 40–100자(벗어나면 경고), **120자 넘으면 오류**. 한두 문장(셋 이상 경고). 독립의 고정 문장은 길이 검사 밖 |
| `later` · `gate` | **본 사람용 짧은 이유** — 화면은 여기까지 읽음이 `gate`(뒤 스토리 단위 키)를 지났을 때만 `text` 뒤에 `later`를 더 보인다(전부 보기면 늘). `later`는 gate까지의 스토리 내용을 써도 된다(더 뒤 이름은 오류). 권장 15–70자, 90자 넘으면 오류, 한 문장. **뒤 필수 스토리로 오른 등급(추천 15 · 준필수 3 — `from`이 그 스토리보다 뒤)은 확정에 꼭 있어야 한다** — `new`가 `gate: from`으로 틀을 만든다. 그 밖(앞 필수 스토리를 딛지만 뒤 스토리와도 이어지는 것 · 연대기 자리가 뒤 챕터인 것)은 있으면 쓴다 |
| `src` | 쓸 때 본 판정의 지문 — why: 등급 · 딛는 자리(`from`) · 이유, when: 화면에 뜨는 좁힘들의 관계(`at`) · 이유. `new`가 채운다. 판정이 바뀌면(다시 판정 · 신작 N3) 지문이 어긋나 **낡음** — 경고, 내보내기에서 빠지고 화면은 거른 판정 문장으로 돌아간다. 고친 뒤 `new … --refresh`로 지문을 새로 하고 다시 확정 |
| `status` · `reviews` | 해석 기록이라 `후보` → Claude가 칸마다 검토해 `확정`(CLAUDE.md "해석이 필요한 기록"). 확정 검토에 내용 지문 `hash`(문장 + src, later가 있으면 later · gate도) — 확정 뒤 고치면 오류, 다시 `set … 확정`. 사용자가 마지막으로 결정한 칸은 Claude가 바꾸지 않는다 |
| `session` · `by` · `date` | 쓴 세션 · 쓴 쪽 · 날짜 |

### 쓰는 기준 (W14a, 사용자 조율 2026-10-10)

1. **꼴 — "이 스토리를 읽으면 무엇을 알게 되나".** 팬이 얻는 것(인물의 순간 · 사정 · 세계의 한 면)을 쓴다. 앞 필수 스토리가 설명 없이 넘긴 것을 채우면 그 자리까지("CH.06에서 '나중에 말하겠다'던 이야기 — …").
   무슨 이야기인지는 한 줄 소개(공개 개요 `logline`)가 바로 위에서 한다 — **되풀이하지 않는다**. 이유 칸은 "왜 읽나".
2. **위 줄이 하는 말은 쓰지 않는다** — 읽는 때("CH.44 전에 봐 두면 좋다")는 리더의 '언제 읽나' 줄이, 등급은 칩이, 연대기 자리는 카드의 굵은 줄이 말한다.
   위 줄(선행 · 이 스토리가 선행인 곳 · 언제 읽나)과 어긋나지도 않게 — 뒷이야기가 있는 스토리를 "이 안에서 끝난다"고 쓰지 않는다(FULL FOOL DAY → LIAR'S END).
3. **등급마다 무게**
   - 준필수: 이 스토리에만 있는 결정적 순간. "스노우 화이트가 … 결심하는 순간이 여기 있다."
   - 추천: 필수 스토리 인물 · 사건의 앞사정 · 까닭. "OVER ZONE에서 검만 남기고 죽었다던 홍련의 언니, 장화가 왜 그렇게 죽었는지가 여기 있다."
   - 참고: 더 알게 되는 세계 · 인물의 한 면(필수 스토리 인물의 새 사정 · 방주 사회 · 지상 요령).
   - 독립: 이 스토리에서 알게 되는 세계 · 인물 사정이 있으면 그것을 한 문장. 소동극 · 일화뿐이라 이을 것이 없으면 **고정 문장 `필수 스토리와 얽히지 않는 이야기.`**(`STANDALONE_TEXT` — 길이 검사 밖, 독립 밖에 쓰면 오류).
4. **연대기 추정 이유(`when`)** — "왜 그때로 보나": 이 스토리 · 앞 스토리의 단서(누구를 이미 안다 · 누가 어디 있다 · 어떤 차림이다)로. 판정 말(상한 · 하한 · 모습 코드 · 1회독)은 팬 말로(코드 → 차림 · 모습).
   자리의 뒤 끝이 뒤 스토리에서 오면(그 스토리에서 처지가 바뀐다) text 끝을 "~하던 때로 본다"로 쓰지 않는다 — '던'이 앞날을 암시한다. "이 모습으로 때를 가늠한다"로 쓰고 까닭은 `later`에(W14c).
   원본 이유가 여럿이면 화면 자리(굵은 줄)를 세우는 것만 묶는다 — 자리와 다른 챕터를 꺼내는 곁가지 단서는 뺀다(W14c).
5. **스포일러가 먼저다**(사용자, 2026-10-10 — "44 안 본 사람에게 스포", "스포 관련을 우선 순위로, 이미 본 사람이면 이유 짤막하게").
   - `text`(누구에게나): 그 스토리와 앞 스토리 내용만 — 뒤 스토리는 이름도 암시도 쓰지 않는다. 뒤 필수 스토리 때문에 오른 등급(추천 15 · 준필수 3)도 접지 않고 이 스토리 내용만으로("버닝엄 부사령관은 지휘관을 엔더슨 쪽 사람으로 보면서도 … 아들 일만은 지휘관에게 맡긴다"). 뒤에 밝혀지는 정체 · 처지 변화 · "~부터다" 같은 앞날 암시도 쓰지 않는다.
   - `later`(gate를 본 사람에게만): 뒤 스토리와 이어지는 까닭을 짧게 한 문장 — "CH.44에서 버닝엄이 아들의 일로 지휘관을 믿는 까닭이 이 이야기다." gate는 문장이 쓰는 가장 뒤 스토리(뒤 필수 스토리로 오른 등급은 보통 `from`).
   **검사가 잡는다**: `text`에 그 스토리보다 읽는 순서가 뒤인 메인 챕터(`CH.44`) · 제목 단위(`GODDESS FALL` — 같은 제목이 여럿이면 처음 나온 자리)가 있으면 오류, `later`는 gate보다 뒤면 오류. 스포일러 이름 검사도 `later`는 gate 자리로 잰다. 입력 묶음은 기록 · 단위마다 `[앞]` · `[뒤 — 쓰지 않음]`을 붙인다.
6. **화면 말로** — 척추 → 필수 스토리. 판정 말(척추 · 판정 · 등급 · 잣대 · 문턱 · 상한 · 하한 · 빌드업)은 오류, 작업 냄새(기록 · 근거 · 요지 · 단서 · 주요 인물 · 주역)는 경고 — 작품 속 물건(세이렌이 쓴 기록)이면 그대로.
   게임 · 기록의 대괄호 용어(`[해결사]`)는 괄호를 걷고 쓴다 — 괄호가 남으면 오류(W14b).
   ID · 단위 키 · 줄 번호 · 세션 이름은 공개 개요와 같은 오류. 말투는 공개 개요와 같은 한다체, 지휘관은 "지휘관".
7. **사실은 기록으로 맞춘다** — 판정 이유는 해석이라 그 속 사실은 입력 묶음이 풀어 준 기록 문장으로 확인하고, 모호하면 그 씬만 `read.mjs`. 따옴표는 이름 · 용어 · 짧은 말(20자 안쪽) 한 번까지. 외부 참고 표는 열지 않는다.

**도구** — `tools/blurbs.mjs`(모델 `tools/blurbs/model.mjs` · 입력 `tools/blurbs/input.mjs`, 테스트 `tests/blurbs.test.mjs`). 원본 · 입력은 내보낸 사이트 데이터(`site/data`)를 읽는다.
공개 개요의 원문 겹침 · 스포일러 이름 검사(`tools/synopsis/model.mjs` `overlapProblems` · `spoilerProblems`)를 같이 쓴다.

```bash

node tools/blurbs.mjs new sub:세르반_03 --refresh                          # 낡은 칸의 지문을 지금 판정으로 바꾸고 후보로(고친 뒤)
node tools/blurbs.mjs check [단위 …] [--all]                               # 검사 — 오류면 종료 코드 1. --all이면 안 쓴 단위 수도
```

## 시점별 판 — `annotations/versions/<대상>.json` (W15c, 2026-10-10)

떡밥 줄기의 `title` · `text`(위 "떡밥 줄기")는 **결말을 아는 자리에서 쓴 분석용 이름**이다 — 화면이 첫 스토리를 봤는지만 보고 그대로 띄우면 뒤 이름 · 정체 · 결말이 샌다(SESSIONS.md W15).
분석용 이름은 그대로 두고, **화면용 제목 · 요약을 읽은 자리마다 따로 쓴다** — 떡밥마다 판 여럿, 판마다 "이 스토리를 본 사람에게 보이는 제목 · 요약".
화면은 앞 판들의 at을 다 본 마지막 판을 고른다(`fmt.versionAt` · `fmt.threadAt` — 판이 없으면 떡밥의 마지막 스토리를 봤거나 전부 보기일 때만 분석용 이름).
내보내기 `tools/site/export/versions.mjs` → `site/data/versions.json`(앞에서부터 확정 · 고치지 않음 · 낡지 않음 · 검사 오류 없는 판이 이어지는 데까지 — 빠진 판은 화면이 그 앞 판을 보인다. 덜 아는 쪽이라 새지 않는다).
도구는 `tools/versions.mjs`, 세션은 SESSIONS.md W15c(형식 · 시안) · W15d(60 전부 · 화면) · W15e(사전 설명 — 아래 "사전 설명 판").

파일 이름은 대상 키 규칙(`thread:J30` → `thread.J30.json`). 예시: `annotations/versions/thread.J30.json`.

```json
{
  "subject": "thread:J30",
  "versions": [
    { "at": "char:222", "title": "홍련 — 약속, 아니 저주", "text": "홍련은 전멸한 근접전 스쿼드의 유일한 생존자인가 — …",
      "src": "3e00b2a57c", "session": "W15c", "by": "claude", "date": "2026-10-10", "status": "확정",
      "reviews": [{ "decision": "확정", "by": "claude", "date": "2026-10-10", "session": "W15c", "hash": "c84098ee25", "note": "…" }] },
    { "at": "erelic:red_ash_lost", "title": "홍련 — 궤멸한 근접전 부대", "text": "…" }
  ]
}
```

| 칸 | 뜻 |
|---|---|
| `at` | 이 판이 보이기 시작하는 스토리(단위 키). **첫 판의 at = 떡밥이 처음 나온 스토리**(`threads.json` `first_unit` — 그 앞이면 떡밥이 '아직 나오지 않음'). 판은 읽는 순서대로, 떡밥이 마지막으로 움직인 스토리(`last_unit`)까지. 떡밥이 움직이지 않은 스토리면 경고 |
| `title` | 화면 제목 — 떡밥 탭 목록 · 관계도 · 연결 탭 고르기 칸 · 리더 머리 등. 권장 2–30자, **40자 넘으면 오류**. 꼴은 줄기 title처럼 "중심 — 갈래 · 갈래" |
| `text` | 화면 요약 한두 문장 — 권장 25–120자, **200자 넘으면 오류** |
| `src` | 쓸 때 본 떡밥 흐름의 지문 — at까지(읽는 순서) 떡밥이 움직인 자리(`threads-flow.json` points · echoes의 기록 · 단계 · 스토리). at 앞의 흐름이 바뀌면(2회독 바로잡기 · 신작 N3) **낡음** — 경고, 내보내기에서 빠진다. 고친 뒤 `new … --refresh`로 다시 재고 확정. at 뒤가 바뀌는 것은 상관없다 |
| `status` · `reviews` | 해석 기록이라 `후보` → Claude가 판마다 검토해 `확정`(CLAUDE.md "해석이 필요한 기록"). 확정 검토에 내용 지문 `hash`(at · 제목 · 요약 · src) — 확정 뒤 고치면 오류, 다시 `set … 확정` |
| `session` · `by` · `date` | 쓴 세션 · 쓴 쪽 · 날짜 |

### 쓰는 기준 (W15c, 2026-10-10)

1. **판 = 그 자리 독자가 이 떡밥을 무엇이라 부르고 무엇을 궁금해하나.** 판의 글은 at까지의 스토리 내용만(읽는 순서) — 입력 묶음의 흐름에서 at 앞 줄(제기 · 처음 밝혀짐 · 회수 기록 문장)로 쓴다. 분석용 이름 · 요약은 옮기지 않는다(결말을 아는 자리의 말이다).
2. **첫 판은 그 떡밥이 처음 나온 스토리에서 아는 것만** — 그 자리의 의문 꼴 그대로. 뒤에서 이 떡밥의 중심이 될 이름 · 정체를 미리 부르지 않는다. 제목도 그 자리의 말로("지휘관의 정체"가 아니라 첫 의문 "카운터스를 시험하는 사령부", "그레이브"가 아니라 "관을 짊어진 존재").
3. **판을 나누는 때 — 떡밥의 얼굴이 바뀔 때만.** ① 떡밥의 중심 물음에 답이 나와 앞 판의 물음이 낡을 때(정체가 드러남 · 큰 회수 · 뒤집힘) ② 새 물음이 서서 떡밥이 넓어질 때(새 인물 · 새 갈래가 떡밥에 든다) ③ 그래서 제목의 이름이 바뀔 때. 암시 · 재언급 · 보강, 작은 일부 회수, 같은 스토리에서 서고 풀리는 곁가지 의문은 판을 세우지 않는다. 가까운 고비 둘은 뒤 것 하나로 묶는다(입력 묶음의 ★가 후보 자리).
   판 수는 독립 1–2, 보강 2–5, 뼈대 4–6(6 넘으면 경고). 판이 모자라 독자가 앞 판을 조금 오래 보는 것은 괜찮다 — 판이 늦는 것은 새지 않고, 이르면 샌다.
4. **떡밥 묶음 자체가 스포일러다** — 줄기에 든 의문이라도 그 자리 독자가 이 떡밥과 이어진 줄 모르면 판 글에 넣지 않는다(마리안 떡밥의 '병원의 소녀'는 그 소녀가 마리안과 관계있느냐는 물음이 선 CH.13 전에는 쓰지 않는다 — CH.05 판에 넣으면 묶음이 정체를 흘린다).
5. **이름은 그 자리에서 아는 이름만** — 대상의 처음 나온 자리(W15b `meet` · 표준명이 늦은 대상 `name_meet` · 다른 이름 `meet`)가 at 뒤면 쓰지 않는다(**검사가 오류로 잡는다** — 입력 묶음 끝에 이름마다 처음 쓰이는 자리). 정체 연결(두 이름이 한 인물)이 at 뒤에 드러나면 두 이름을 한 글에 같이 쓰지 않는다(경고). 뒤 메인 챕터 · 제목 단위 이름은 오류(팬용 문장과 같은 검사).
6. **마지막 판은 떡밥이 마지막으로 크게 움직인 스토리** — 그 자리 독자가 아는 것 전부로, 아직 열린 물음이 있으면 물음 꼴로. 분석용 이름과 같아도 된다.
7. **말** — 제목은 이름 · 명사구, 요약은 "~인가 / ~나" 물음 꼴이나 "드러난 것 — 남은 물음" 꼴. 한다체. 판정 말(척추 · 등급 …)은 오류, 기록 표기 괄호(`[블랙박스]`)는 걷는다(오류). 따옴표는 이름 · 짧은 말 한 번까지. 사실은 기록 문장으로 맞추고, 앞날을 암시하는 말("~하던 때", "~가 되기 전")은 쓰지 않는다. 외부 참고 표는 열지 않는다.
8. **W15d에서 더한 것(60 떡밥 쓰며 정함)** — 체크 칸 스토리는 units.json grade로 가른다(spine이고 메인이 아닌 것 + grade '필수' — 이벤트 유실물이라도 준필수면 체크 칸, 그 밖의 유실물 · 추천 이벤트는 출시 순서대로 보이는 것).
   체크 칸 스토리가 여럿 이어지면 큰 정보가 처음 드러나는 한 곳에만 판을 두고, 나머지 체크 칸에서만 나온 내용은 쓰지 않는다. **메인 챕터의 내용을 체크 칸 판에 묶지 않는다**(그 칸을 안 고른 독자는 거기서 멈춘다 — 메인 고비는 메인 자리 판에).
   흐름의 ★(처음 밝혀짐) 자리라도 그 스토리 원문이 이 떡밥과 잇지 않으면 판을 연결이 서는 뒤 자리로 미룬다(J9 CH.43 · J27). 가까운 고비 여럿은 그 무리의 마지막 메인 챕터 하나로 묶는다.
   마지막으로 움직인 스토리가 새 물음 하나만 세우는 작은 움직임이면 판을 두지 않아도 된다(기준 6의 '크게'). 독립 떡밥은 얼굴이 셋이어도 가운데를 뒤 판에 묶어 2판을 지킨다.
   대상 목록에 없는 이름(장소 · 조직 — 입력 묶음의 "처음 쓰이는 자리"에 없는 것)은 원문으로 처음 나온 자리를 확인한다. 스토리 제목에만 나오는 이름 · `#`으로 시작하는 이름은 검사가 오류로 잡는다 — 그 자리에선 이름 없는 말로.

**체크 칸 스토리**(척추 이벤트 · 사이드 · 준필수 — '봤음'을 사람이 고른다): 화면은 **앞 판들의 at을 다 본 마지막 판**을 고른다(`fmt.versionAt`) — 뒤 판은 앞 판들의 내용 위에 쓰므로,
체크 칸 스토리에 at이 있는 판을 안 고른 독자는 그 판 앞에서 멈춘다(새지 않는다). 그래서 **체크 칸 스토리에서만 드러난 것을 뒤 판에 쓰면 그 스토리에 판을 둔다** — 판 없이 쓰면 그 스토리만 건너뛴 독자에게 샌다.
내보내기도 앞에서부터 성한 판까지만 싣는다(중간 판이 낡거나 고쳐지면 그 뒤 판도 뺀다). 첫 스토리가 체크 칸인 떡밥은 J28 하나(SECOND AFFECTION) — 그 스토리를 안 고르면 떡밥은 '아직 나오지 않음'.

```bash
node tools/versions.mjs new J30 [--at erelic:red_ash_lost] [--session W15d]   # 입력 묶음(분석용 이름 · 첫 스토리 · 흐름 ★ · 이름이 처음 쓰이는 자리 · 지금 판) + 틀(첫 판 at = first_unit) · --at으로 판 틀을 더한다
node tools/versions.mjs new J30 --refresh                                        # 낡은 판의 지문을 지금 흐름으로 바꾸고 후보로(고친 뒤)
node tools/versions.mjs check [J30 …] [--all]                                    # 검사 — 오류면 종료 코드 1(원문 겹침 · DB 이름 경고 포함). --all이면 판 없는 떡밥 수도
node tools/versions.mjs set J30 char:222 erelic:red_ash_lost 확정 --note "…"    # 확정 전에 검사(오류면 확정 안 함)
node tools/versions.mjs progress                                                 # 중요도별 진행률 · 사전 종류별 진행률
```

### 사전 설명 판 (W15e, 2026-10-10)

세계 탭 · 리더 · 세계 탭 찾기의 **비인물 항목 설명**(사전 `note` — 개념 · 사건 · 물건 · 조직 · 장소 170, 처음 나온 자리가 없는 org:에덴은 빼 169)도 같은 꼴로 판을 둔다.
분석용 설명(`annotations/dictionary/*.json` `note`)은 그대로 두고, 화면은 판을 보인다(`fmt.noteAt` — 판이 없으면 전부 보기에서만 분석용 설명).

- 파일 `annotations/versions/<대상 ID>.json`(`place:방주` → `place.방주.json`), `subject`는 대상 ID. 판은 `{ at, text, src, … }` — **제목이 없다**(이름은 W15b `fmt.nameAt`이 고른다 — `title`을 두면 오류).
- **첫 판 at = 항목이 처음 나온 자리** = `targets.json meet`의 마지막(체크 칸 스토리가 아닌 첫 스토리 — 그 앞 체크 칸을 안 골라도 여기서는 만난다). 그 앞 체크 칸 스토리만 본 독자는 이름만 보고 설명은 비어 있다(늦는 쪽이라 새지 않는다).
- `src` = at까지(읽는 순서) 항목을 다룬 기록(about에 든 records*.json 기록)의 [기록, 단위] — at 앞에 기록이 더해지거나 빠지면 낡음. 마지막 자리 한도는 없다. 항목을 다룬 기록이 없는 스토리의 판은 경고.
- 한도: 10–100자 권장, 160자 넘으면 오류, 한두 문장, 판 4개 넘으면 경고.

쓰는 기준 — 위 1–8을 따르되 사전 설명에 맞춰:

1. **판 = 그 자리 독자에게 이 항목이 무엇인가** — 정의 한두 문장. 입력 묶음의 at 앞 기록 · 무엇인지 보여 주는 줄로 쓰고, 문장마다 at까지의 기록이나 원문(`read.mjs`)으로 확인한다.
   분석용 설명은 대부분 처음 더한 스토리에서 쓴 것이라 그 자리에서 새지 않으면 작업 표기를 걷고 다듬어 써도 된다 — 다만 뒤에서 더한 마디(정체 · 기원 · 결말)는 뺀다.
2. **판을 나누는 때 — 항목이 무엇인지의 답이 바뀌거나 크게 넓어질 때만**: 정체 · 내막 · 기원이 드러남, 처음엔 이름만 나왔다가 무엇인지 드러남, 처음 알던 것이 뒤집힘. 등장 일화 · 세부 · 새 사례는 판을 세우지 않는다. 대부분 1판, 많아야 3판. 화면은 그 자리 판 하나만 보이므로 뒤 판도 혼자 읽어 무엇인지 알게 앞 판의 핵심 정의를 이어 쓴다.
3. **체크 칸 스토리** — 기준 8 그대로: 체크 칸에서만 드러난 것을 뒤 판에 쓰려면 그 스토리에 판을 두고, 메인 챕터의 내용은 메인 자리 판에 둔다(체크 칸 판에 묶으면 그 칸을 안 고른 독자가 멈춘다). 체크 칸에서만 나온 세부는 되도록 쓰지 않는다.
4. **이름** — 그 자리에서 아는 이름만(검사 오류). 항목 제 이름은 머리에 보이므로 설명 첫머리에 되풀이하지 않는다. 표준명이 늦은 항목(`name_meet`)은 제 표준명도 그 자리 전엔 쓰지 않는다.
5. **말** — 사전 정의 꼴(명사구로 끝나도 된다 — "인류가 사는 지하 도시"), 한다체. 정체가 열려 있으면 "~인지는 아직 모른다" 꼴. 작업 표기(단위 키 · '메신저 계정 이름표로도 나온다' · '○○에만 나온다' · 이름 쓰임 설명)는 쓰지 않는다 — 독자 화면 글이다. 원문 인용은 짧은 말 한 번까지.
6. **첫 자리에 이름만 나오는 항목**(방주 CH.00 · 갓데시움 CH.13) — 첫 판은 그 자리에서 아는 만큼 얇게("~라고만 나온다 — 무엇인지는 아직 모른다") 두고, 무엇인지 드러나는 다음 자리에 판을 세운다.
7. **기록이 없거나 적은 항목** — 무엇인지 보여 주는 줄과 처음 나온 장면을 `read.mjs`로 읽어 쓴다. 그 자리 원문만으로 무엇인지 모르면 그 자리에서 아는 만큼만("○○가 다니는 학교").

```bash
node tools/versions.mjs new place:방주 [--at ch10] [--full] --session W15e   # 입력 묶음(분석용 설명 · 처음 나온 자리 · 다른 이름 · 근거 줄 · 다룬 기록 · 이름이 처음 쓰이는 자리) + 첫 판 틀
node tools/versions.mjs check place:방주                                     # 검사
node tools/versions.mjs set place:방주 ch01 확정 --note "…" --session W15e
```

## `read.mjs --num`

1회독 · 2회독은 `node tools/read.mjs <키> --num`으로 읽는다. 줄마다 `#N `이 붙어 글자 수가 약 17% 는다
(메인 140만 → 164만 자, 이벤트 378만 → 445만 자). 파트 경계도 `--num` 기준으로 다시 잰다 — 한 파트는 그대로 2만 자 이하라
`--num` 없이 읽을 때와 파트 번호가 다를 수 있다. docs/history/reading.md 계획 분량(세션당 10만 자 이하)은 `--num` 없는 글자 수다(Q-A3-1).
