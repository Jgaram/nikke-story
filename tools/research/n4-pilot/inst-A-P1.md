# Pilot A · 조건 P1 — 단위 맞춤 의문 목록 + 회수 훑기 + 추정 회수 허용

이 단위를 읽고 기록한다. P0와 다른 점은 셋이다: (1) 인계에 **이 단위 맞춤 의문 목록**이 있다 (2) 읽은 뒤 **회수 훑기**를 따로 한다 (3) 회수 기준이 **추정 회수를 허용**한다.

## 먼저 읽을 것
1. `questions-matched.md` — 이 단위 앞까지의 열린 · 일부 풀린 의문 가운데 기계가 고른 것: (1) 이 원문과 낱말이 겹치는 의문 (2) 이 단위에 나오는 대상을 다루는 떡밥 줄기에 든 의문. 기계가 고른 것이라 우연한 겹침도 있고, 여기 없는 의문이 풀릴 수도 있다.
2. `questions-all.md` — 열린 의문 전부. **처음부터 읽지 않는다.** 아래 4단계에서만 훑는다.
3. `text.md` — 이 단위 원문(read.mjs 출력 그대로).

## 절차 — 한 번 읽고 두 번 훑는다
1. **주시 목록** — 원문을 읽기 전에 `questions-matched.md`를 훑고 "이 원문에서 풀릴 법한 의문"을 3–10개 고른다. 왜 그런지 한 줄씩(`watch`).
2. **읽으며 기록** — 사실 · 새 의문 · 시점을 적는다(P0와 같은 칸 — 아래).
3. **회수 훑기** — `questions-matched.md`의 의문을 **하나씩** 다시 보며 판정한다. 주시 목록에 없던 것도 모두 본다. 판정은 `sweep`에 의문마다 한 줄: `회수 전부` · `회수 일부` · `아님` · `보류`(원문을 더 봐야 함). "아님"은 한 줄 이유면 된다.
4. **전체 목록 훑기** — `questions-all.md`를 빠르게 한 번 훑어, 맞춤 목록에 없는데 이 단위에서 풀린 의문이 있으면 더한다(`sweep`에 `출처: 전체`로 표시).

## 회수 기준 (새)
- 원문이 그 의문을 **직접 이어 주지 않아도**, 이 단위의 사실이 그 의문의 **대상 · 상황 · 시점과 맞아** 독자가 "아, 그게 그거였구나" 할 수 있으면 회수로 적는다. 확신도: 원문이 직접 이으면 `확실`, 독자의 추론이면 `추정`.
- 의문에 물음이 둘 이상이면(`—`로 이어진 것 등) **어느 물음이 풀렸는지**를 적고, 핵심 물음(의문의 앞쪽 · 제목 격)이 풀렸으면 `전부`, 곁 물음만 풀렸으면 `일부`. 남는 물음은 `remaining`에 문장째.
- 같은 수수께끼로 보이는 의문이 목록에 둘 이상이면(`같은 소녀` 등) `same_as`로 묶어 적는다.
- 반대로 이 단위가 앞 의문을 **더 키우거나 뒤집으면**(답이 아니라 새 단서) `회수`가 아니라 `단서`로 적는다 — `{ "question": "Q…", "act": "단서", … }`.

## 무엇을 남기나
- `summary`(300–1,000자) · `facts`(`N1` …, `about` 포함) · `questions`(`NQ1` …) · `times` · `slips` — P0와 같다.
- `watch` — 1단계 주시 목록 `[ { "question": "Q10", "why": "…" } ]`.
- `payoffs` — 회수 · 단서 `{ "question": "Q10", "act": "회수"|"단서", "answer": "N3", "degree": "전부"|"일부", "remaining": "…", "evidence", "reason", "confidence" }`.
- `sweep` — 3 · 4단계 판정 전부 `[ { "question": "Q10", "decision": "회수 전부"|"회수 일부"|"아님"|"보류", "note": "한 줄", "source": "맞춤"|"전체" } ]`.
- `same_as` — `[ ["Q20", "Q63"] ]`.

## 출력
`{OUT}` 에 JSON 하나 (`"condition": "P1"`), 끝에 `"memo"`(읽기 메모 — 특히 3 · 4단계에 든 품과 전체 목록 훑기가 실제로 도움이 됐는지).
